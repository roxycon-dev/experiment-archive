# HRDecoder-JointContext：最终架构方案

2026-10-17。由主代理亲自修订、复核。**本文件是新的统一设计，取代05候选方案；设计已成稿，尚未实现、尚未训练。** 本轮不消耗正式训练机会。目录中的model.py、train.py和protocol.json仍对应已完成的v3，不能直接作为本方案的执行入口。

最终选择：**一个共享ImageNet HRNet-W48，同时提取1024整图上下文与2048原生细节；两路在特征层交互，由一个非线性分类头作最终判断。主损失汇总同一步两张图的Dice统计量，整批缺少某类时才使用该类的负例BCE。** 保留原HRDecoder的M4特征裁块辅助监督。

固定条件：同一预训练文件、同一融合标签、40,000次SGD更新、每次2张原图，目标为固定40k权重的val mIoU严格超过45.32183122738841%，再按既有协议评估test是否超过45.860383832668%。机器规格见[jointcontext_spec.json](D:/dataset/experiment/HRDecoder_NativePyramid_20261011/review_20261017/jointcontext_spec.json)。

## 2. 唯一主路径与张量尺寸

每步两张图经过一次既有增强，得到X∈R^(2×3×2048×2048)。从同一X构造G视图U1024(X)与N视图X，不能分别重新采样增强。

|位置|G：1024输入|N：2048输入|
|---|---|---|
|W48第1分支|48×256×256|48×512×512|
|第2分支|96×128×128|96×256×256|
|第3分支|192×64×64|192×128×128|
|第4分支|384×32×32|384×64×64|
|对齐到本视图第1分支并拼接|FG720：720×256×256|FN720：720×512×512|
|共享投影P|64×256×256|64×512×512|
|投影后对齐|G：64×512×512|N：64×512×512|

表中省略batch维。主干是一份共享参数，不是两份独立可训练W48。主干内部31处多尺度融合上采样统一为bilinear、align_corners=False。本文所有双线性插值均使用align_corners=False、antialias=False。

投影及主头严格定义为：

~~~text
P_domain(F) = ReLU(BN_domain(Conv1x1_720→64(F)))
G = U512(P_G(FG720))
N = P_N(FN720)

C = (N + G) / 2
D = (N - G) / 2
A = Conv7x7(C, Kc) + Conv7x7(D, Kd)
H = ReLU(BN_main(A))
z512 = Conv1x1_64→4(H)
Z = U2048(z512)
~~~

两组7×7卷积均为64→64、padding=3、dilation=1、无bias；投影卷积无bias，最终四类分类器有bias。没有额外ASPP、浅层RGB预测、PixelShuffle、自由logit残差、标量门控或dropout。**最终只有一个四通道预测Z。**

共同/差异表示可逆：N=C+D，G=C−D，故在进入卷积前不因平均而丢弃两路差异。并且：

~~~text
Conv(C,Kc) + Conv(D,Kd)
  = Conv(N,(Kc+Kd)/2) + Conv(G,(Kc-Kd)/2)
~~~

它等价于对两路特征拼接后的可学习卷积，而不固定两路最终预测的权重。Kd=Kc时主头卷积只读取N；Kd=−Kc时只读取G。一般情况下可利用二者的不同通道和邻域信息，再经过BN/ReLU完成联合分类。这是表达能力上的事实，不表示优化过程必然找到最优组合，也不表示完整模型严格包含历史B0全部预测过程。

## 3. 初始化与首步梯度

W48只加载指定ImageNet预训练权重，逐键核对1,830个主干张量，明确排除126个分类张量；不使用B0、v3、融合模型或其他病灶任务训练权重。

新头初始化使用独立seed=42：依次初始化P、Kc、分类器；P和Kc使用Kaiming normal、fan_out、ReLU，分类器权重Normal(0,0.01)、bias=0。随后创建全零Kd及BN缓冲区，不能让Kd的临时随机初始化改变前述随机序列。新头BN的gamma=1、beta=0，running_mean=0、running_var=1、counter=0。不沿用v3的−4.6分类偏置。

Kd从零开始，目的在于先建立共同上下文，再学习尺度差异；**最终输出卷积及共同路径Kc均非零初始化。** 若g为A上的上游梯度，则：

~~~text
∂L/∂N = 1/2 (Kcᵀ + Kdᵀ) g
∂L/∂G = 1/2 (Kcᵀ - Kdᵀ) g
~~~

Kd=0时，两路均保留经过Kc的反传通路；Kd自身也可由D与g形成首步权重梯度。此处“保留通路”不等于任意样本、任意ReLU状态下每个参数梯度都非零。

|可训练部分|参数量|
|---|---:|
|P的1×1卷积及BN affine|46,208|
|Kc的7×7卷积|200,704|
|Kd的7×7卷积|200,704|
|主/辅助共享的头部BN affine|128|
|共享四类分类器|260|
|解码器合计|448,004|
|共享W48|65,325,120|
|全模型|65,773,124|

BN分域只增加缓冲区，不复制gamma/beta。相比247,300参数的原FCN头增加200,704参数；本方案不声称参数量或计算量与原模型相等。

## 4. 主损失：两图汇总，整批空类使用负例监督

标签定义为0背景、1 EX、2 HE、3 SE、4 MA、255忽略。四类使用独立sigmoid，不加入第五个背景分类通道。

对每类c，令v表示label≠255，y_c表示该类GT，p_c=sigmoid(Z_c)，所有Σ均先覆盖本步两张图的有效像素：

~~~text
P_c = Σ(v y_c)
V   = Σv
ε   = 1e-5

当 P_c > 0：
  L_c = 1 - (2 Σ(v p_c y_c) + ε) / (Σ(v p_c²) + P_c + ε)

当 P_c = 0 且 V > 0：
  L_c = Σ_valid softplus(Z_c) / V

L_main = (L_EX + L_HE + L_SE + L_MA) / 4
~~~

先筛选有效位置，再执行sigmoid/softplus及归约；归约为FP32。不能先对255位置产生非法数再乘零。整个主batch均为ignore时，在模型前向前报错，不能产生无监督的优化或BN更新。合法监督位置出现非有限数也必须显式报错。

这保留了有阳性时原平方Dice的形式，仅改变跨图归约。当一张图有该类、另一张没有时，两图的负例共同进入同一个分母，负例梯度不再只依赖空图Dice的epsilon分子。当两张都没有该类时，负例softplus的logit导数为p/V；高置信误检仍有直接监督。没有新增class weight或可调损失混合系数。

对有阳性的情况，设A=2Σpy+ε、B=Σp²+P+ε，单个有效logit的导数为：

~~~text
∂L_c/∂z_i = (2 A p_i / B² - 2 y_i / B) p_i(1-p_i)
~~~

该导数对正例非正、对负例非负；这描述独立logit上的方向，**不构成共享网络参数更新后每个像素都改善的证明**。两图soft Dice也不是整个验证集离散mIoU的无偏估计。这里修正的是已确认的监督归约缺口，不把代理损失等同于最终指标。

## 5. M4辅助监督的完整定义

M4仅使用G路径的FG720特征，不新增RGB编码。每步用独立、持久的numpy RandomState(42)抽一个r∈[0.75,1.25)，裁块边长h=8 floor(1024r/8)。抽取4个空间框，两张图共享这些框，最多形成8个裁块实例。

每个坐标使用原helper的规则：

~~~text
offset = 8 * randint(0, floor((2048-h+1)/8))   # 上界不包含
~~~

不能顺手改成包含末端、按类别重采样或每张图分别抽r。裁框坐标除以8得到FG720的整数框；裁出的特征双线性放大至256×256。标签直接从2048画布截取对应h×h区域，不把标签先缩到256。

**先按标签排除全255的裁块实例，再将其余实例拼成一个batch、调用辅助头一次：**

~~~text
crop(FG720) → resize256 → P_aux → Kc → BN_aux → ReLU → 同一分类器
~~~

辅助logits以FP32双线性放大到h×h，与原裁块标签比较。Kd不参与此路；辅助路径训练共享语义投影、共同卷积和分类器。保留有效背景裁块，不把“没有病灶”误当成“没有监督”。

辅助损失仍为每个有效实例、每个类别分别计算的平方Dice，ε=1e−5，显式屏蔽255；先四类平均，再对有效实例平均。**它不改用主损失的整批空类BCE，也不跨实例池化。**

~~~text
L_total = L_main + 0.1 * L_M4
~~~

若8个实例全部被排除，令L_M4=0并跳过辅助头及其BN更新，正常计算有效主损失。不能重抽直到有病灶，也不能再额外除以4。M4只在训练使用，推理不加入裁块预测平均。

## 6. BN状态与精确反传的执行约定

|BN所在位置|独立running统计域|共享内容|
|---|---|---|
|W48各BN|G、N|唯一gamma/beta|
|投影P的BN|G、N、aux|唯一gamma/beta|
|7×7卷积后的BN|main、aux|唯一gamma/beta|

所有BN设eps=1e−5、momentum=0.1。训练归一化使用有偏batch方差，running_var写入无偏估计。主干G/N初始缓冲区分别复制同一预训练BN状态，头部缓冲区按第3节初始化；推理分别读取对应域的running统计，主预测只读取main头域。辅助路径更新与主路径分离。

训练采用**单设备、每次编码器前向物理batch=2**。不能沿用v3逐图循环或普通micro batch1累积来替代该BN语义。本版不同时保留DDP/SyncBN作为另一套可选实现。

为避免同时保留两路完整主干反传图，使用“两阶段编码器重计算”。每一步流程如下：

1. 校验图像、标签和有效监督，生成两个视图及本步M4框；仅清空一次梯度，参数保持不变。
2. 依次在no_grad下编码G、N，但BN仍使用训练批统计，各自域的running统计只更新一次。保留每路四个输出特征，将其detach后设为需要梯度的叶节点。
3. 在这些特征叶节点上执行完整解码器、主损失和辅助损失，反传一次。保留解码器参数梯度和每路四个特征伴随梯度g_G、g_N。g_G必须包括主路与M4的贡献。释放解码器反传图。
4. 按相同输入、参数、精度重算G主干，再重算N主干；每路均为物理batch2。BN仍用当前批统计，但**禁止重算写入running_mean、running_var及计数器**。分别对四个输出调用带对应g的向量—雅可比反传，累加到共享主干参数梯度，逐路释放图。
5. 所有梯度合并后统一clip一次，再执行唯一一次SGD更新。

链式法则给出的主干梯度为J_Gᵀg_G+J_Nᵀg_N。缓存时detach是计算图分段，不能省略第4步而变成冻结主干；也不能再除以2。第4步的BN不能切eval。域必须作为显式参数传递，不能依赖可能在重算前改变的全局“当前域”变量。

固定模型没有编码器dropout或随机深度。若实现擅自增加随机算子，以上重算条件便不再自动成立。每完成u次正常更新，主干G/N、投影G/N和头部main的计数器相对初始化应各增加u；aux增加量不超过u。重算对所有计数器增加量必须为0。

上述梯度等式是相同前向条件下的实数链式法则；实际BF16/CUDA实现仍需验证缓存与重算的一致性。当前没有完整模型的显存测量，不能用旧单路2048的显存读数宣称本模型已满足某张GPU的容量。

## 7. 固定训练配方与计算预算

|项目|固定值|
|---|---|
|优化器|SGD，lr=0.005，momentum=0.9，weight_decay=0.0005，dampening=0，nesterov=False|
|参数组|所有可训练参数只注册一次；无主干/新头LR倍率|
|更新数与batch|40,000；每更新2张原图，两视图各物理batch2|
|随机性|数据seed42；新头隔离seed42；M4独立RandomState42|
|梯度裁剪|global L2 norm≤5，完整梯度汇合后、SGD前执行一次|
|精度|卷积BF16 autocast；主参数、BN统计、优化器状态、loss使用FP32|
|融合数值|C/D计算及两卷积分支求和FP32；卷积按BF16策略输入；最终logits插值FP32|
|额外训练机制|无EMA、无教师、无任务预训练、无参数冻结、无FP16 scaler跳步|

零基更新t=0,…,39999的学习率：

~~~text
lr(t) = 0.005 * (1 - t/40000) * warmup(t)
warmup(t) = 1e-6 + (1-1e-6)*t/1500,  t < 1500
            1,                       t >= 1500
~~~

已检查边界：t=0为5e−9，1499为0.00480941658654，1500为0.0048125，39999为1.25e−7。每次SGD前设定该步lr，不允许scheduler调用先后造成偏移。

保留clip=5是相对05的修正：当前40k记录不足以证明裁剪导致失败，删除已有有限梯度约束也没有证据支持。裁剪仅限制本步梯度范数，不是训练或泛化稳定性的保证。发现非有限梯度不能通过静默跳步、回滚重试或更换损失来凑满40k。

训练合计80,000原图次、160,000语义编码视图次。由于编码器重计算，实际编码器前向对应320,000图次；这不增加数据或SGD次数，但增加计算。两尺度输入面积合计为1024²+2048²，是原B0单次1024编码的5倍；额外反传重算还增加执行成本。因此本方案满足相同步数与原图batch，**不声称相同FLOPs或运行时间**。
