# Stability Luna 复审结论

日期：2026-10-11。只做文档与源码只读审查；未训练、未运行 SGD、未读取新 test 像素、未改 Python。当前 Python 仍是失败的 v1 原型。

## 阻断项及最小修订

1. 主方案第4节的 top-k 没规定平分值顺序。不同设备/内核可能挑中不同像素，尤其 micro-batch 梯度对齐时会影响复现。固定排序为“logit 降序、有效阴性展平索引升序”，每图每类选前 k。
2. 主方案第6项“出现已学类别零检出”未规定持续次数，可能重演 v1 的单次完整 val 误暂停：当前 `metrics.py` 在历史任一类别 IoU≥5% 后，只要一个 val 节点 recall≤0.1% 就触发；历史 PrivateExpert 的 HE 曾在2k为零、4k恢复。最小修订：一个完整 val 零召回只记诊断；只有曾稳定学会且连续两个完整 val recall≤0.1%才暂停。训练探针“历史 recall≥5%”也不要由一次早期偶然值建立；建议4k以后连续两探针≥5%才标为已学会，随后连续两探针≤0.1%触发。健康触发应保存并标为可诊断、可续接 PAUSED，不做永久淘汰。

## 损失与门槛复核

损失代数静态成立：缺组分子为零且不转移0.25；正像素按全 batch `P_c`、各图 top-k 总和按 `K_c`、阳性图 Dice 按 `A_c`、dense BCE 按有效像素总数 `V` 归一。micro-batch=1 只累加局部分子、用完整 batch 分母，不能乘1/2；ignore 不入任一统计，单图全 ignore 为零、全 batch 全 ignore 拒绝更新。Dice 是每张阳性图等权，可能放大小标注/噪声影响；方案已声明这是混合目标且非全数据 IoU 无偏优化，建议保留为限制。

极负阳性 logit 的 softplus 有局部上行梯度，方案正确限定这不保证共享参数净更新、召回或 mIoU。固定系数及 OHEM 是待验证配方。v1 `losses.py` 仍采用各图组均值及缺组重分配，`train.py` 仍按 micro_batch/2 缩放；这些代码不能视为 v2 已落实。

8块真实训练裁块、每类至少2块阳性、224/256更新点逐类 IoU≥20%并要求 loss 下降，作为短期可学习性门槛可解释；它会拒绝晚些才学会的候选，但方案已明确失败只是不通过预检而非架构定罪。正式全局 mIoU 单次跌15pp的暂停阈值能抓到 Detail 12k→16k约23.66pp和v3 16k→20k约19.93pp坍塌；历史约5–6pp后恢复的回落不会触发。只要健康告警可诊断续接，就没有明显重复早停。

覆盖审计：新增全文读科学正文15篇，累计88/102篇；余14篇运维/元数据资料保留 index_only。逐篇状态已更新到 `coverage_stability_audit.json` 与 `reading_stability_audit.json`，历史补记见 `history_stability_audit.md`。

**结论：损失公式静态通过；以上两处 tie-break 与健康守卫语义修订前，方案一致性审核为有条件未通过。**

## 主文修订后复审（2026-10-11）

只复核第4/5/6节：确定性 top-k 平局顺序、Dice小阳性图噪声限制、正常训练梯度记录与无额外探针反传、两类独立的双节点学习/丢失证据，以及可续接PAUSED与终态失败区分均已写入。未学会告警仍要求4k后三次TP=0并有近期阳性监督；单次val零检出只记录。**修订后通过，无阻断缺陷。**建议再明确“持续未学会”仅用于尚未建立已学状态的类；已学后零TP应只归入“已学会后丢失”。该澄清只影响告警标签，不影响暂停安全性。
