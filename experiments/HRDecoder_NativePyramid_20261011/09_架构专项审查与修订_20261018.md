# JointContext r3：主代理架构专项审查

2026-10-18。审查、推导与取舍均由主代理本人完成。本轮只修改架构方案，没有训练，没有用Luna代替终审。当前统一方案为[07最终架构方案](D:/dataset/experiment/HRDecoder_NativePyramid_20261011/07_HRDecoder_JointContext_最终架构方案_20261017.md)，精确配置为[r3机器规格](D:/dataset/experiment/HRDecoder_NativePyramid_20261011/review_20261018/jointcontext_spec_r3.json)。

**本次实际修改：将两个尺度共用的720→64投影，拆成同值初始化、独立训练的P_G和P_N，包括各自的BN affine。** 其余结构及v2训练配方保持不变。这个修改解除一个可以明确写出的表示限制；不能把解除限制直接等同于已取得5.896280个百分点的提升。

## 1. 先核对真正需要超越的对象

已训练失败的是NativePyramid v3，固定40k验证mIoU为39.425551%；JointContext v2、r3均未训练。r3相对v2的数学比较不是针对v3的消融结果，也不能反推“v3失败就是共用投影造成的”。

目标45.321831%来自下列系统：

~~~text
C_old = D/E/B/E4按3:2:1:1融合，含水平翻转平均及学习型H4 MA修正
P0 = 0.75 C_old + 0.25 U0
P_final = 0.75 P0 + 0.25 S_EMA20k
        = 0.5625 C_old + 0.1875 U0 + 0.25 S_EMA20k
~~~

U0是独立ConvNeXt-S/U-Net类分支；S是DINOv3 ViT-B/16通用预训练后，经过Q16k、F12追加12k、S20k的任务训练链。H4是学习型头，不是又一个固定融合系数。来源：[P0身份配置](D:/dataset/experiment/HRDecoder_FinalDecision_20261005/execution/server_results/configs/p0_identity.json)、[最终选择锁](D:/dataset/experiment/HRDecoder_FinalDecision_20261005/execution/server_results/reports/final_selection_lock.json)、[目标及谱系审计](D:/dataset/experiment/HRDecoder_NativePyramid_20261011/review_20261017/redesign_target_evidence.md)。

同一个W48处理两个尺度，可以提供不同尺度的响应，但不会凭空得到独立ConvNeXt、DINO预训练表征及多个历史训练解的多样性。既往S20k与C20k的匹配对照支持该DINO体系内的空间交互改进，不能把它的百分点收益转移给W48。融合系统的组成用于辨认目标能力，不用于放宽本轮相同预训练、相同40k的条件。

## 2. v2真正存在的表示限制

v2两路投影共用W∈R^(64×720)。即使两路BN统计独立，卷积选取的通道线性组合仍相同：

~~~text
N = ReLU(BN_N(W F_N))
G = U(ReLU(BN_G(W F_G)))
rank(W) ≤ 64，dim ker(W) ≥ 656
~~~

若某个位置的特征变化v落在ker(W)，则W(F+v)=WF；后续BN、ReLU及分类头都看不到这次变化。共同/差异变换可逆，仅说明可以从C/D恢复投影后的N/G，不能恢复被W丢弃的720维信息。这个结论对投影输入成立，不证明真实病灶信息恰好在被丢弃的方向上。

两种尺度使用同一720通道坐标系，因而共享W还强制两者选择同一行空间。r3允许W_N、W_G各自选择64维行空间。例如W_N选择第1—64通道，W_G选择第65—128通道，两个尺度可使用的通道方向并集秩为128；共享W时该并集秩至多64。[代数复算](D:/dataset/experiment/HRDecoder_NativePyramid_20261011/review_20261018/architecture_capacity_audit.json)核对了这一构造。

这里的秩是在**同一个720维通道坐标系中比较两种角色的行空间**。若把两个输入当作1440维联合向量，v2与r3的块对角投影秩都至多128；不能宣称联合信息维度翻倍。

共享投影也可能提供有利的尺度一致性约束。因此独立投影是解除限制，不是数学上已经证明更适合这批真实数据。每路64通道及最后64通道非线性读出的瓶颈仍在。

## 3. 修改后唯一的结构

~~~text
同一增强后的2048图像，batch=2
  ├─ resize1024 → 共享W48[G域] → 四分支对齐/拼接720
  │                              ├─ P_G[G域] → 64 → resize512 → G
  │                              └─ M4特征裁块 → P_G[aux域] → Kc
  │                                                       → 辅助BN/ReLU/同一分类器
  └─ 原生2048 → 共享W48[N域] → 四分支对齐/拼接720
                                 └─ P_N[N域] → 64×512×512 → N

C=(N+G)/√2，D=(N−G)/√2
A=Conv7×7(C,Kc)+Conv7×7(D,Kd)
A → 主BN/ReLU → 同一64→4分类器 → FP32双线性恢复2048
~~~

P_G与P_N的卷积、BN affine独立；P_G的G/aux两域共享affine但隔离running统计。W48仍是一份共享参数，G/N域共享主干affine、隔离running统计。主/aux最终头共享affine与分类器、隔离统计。辅助路不经过P_N和Kd。

共同/差异卷积的主路径仍等价于：

~~~text
Conv(N,W_Nhead)+Conv(G,W_Ghead)
W_Nhead=(Kc+Kd)/√2，W_Ghead=(Kc−Kd)/√2
~~~

该等价描述主路径。若在另一实现中使用这组核坐标，辅助Kc也必须对应为(W_Nhead+W_Ghead)/√2，不能悄悄改成只用W_Ghead后仍宣称完整训练目标等价。

## 4. 能严格证明的包含关系与初始化

令r3中的P_N和P_G参数相等，BN affine相等，G/N/aux缓冲区分别映射v2对应域，其余参数完全相同，则每个输入的预测与v2相同。故就可设定参数与状态的预测函数而言，H_v2⊆H_r3。这里只证明包含，不证明在共享编码器实际可达的特征流形上一定严格扩大，更没有证明包含融合目标的函数族。

初始化按以下唯一顺序：隔离head seed42，初始化P_G、Kc、分类器，创建全零Kd，然后将P_G的卷积和affine数值复制给独立P_N。复制和新模块构造不得改变随机序列，也不能让两个参数共用底层存储。所有新头BN均按gamma=1、beta=0、mean=0、var=1、counter=0建立独立域。

这给出与v2相同初始预测的代数构造；尚未有完整模型运行比对。Kc及分类器非零，Kd零初始化不会整体切断两路主干；特定ReLU状态、特定参数的梯度仍可能为零。

参数重新核算如下：

|部分|参数量|
|---|---:|
|P_G|46,208|
|P_N|46,208|
|Kc与Kd|401,408|
|共享头BN affine与分类器|388|
|全部解码器|494,212|
|共享W48|65,325,120|
|全模型|65,819,332|

比v2增加46,208，约为v2全模型的0.07025%。v2已经对两尺度分别调用投影，r3拆分本身不增加该部分理论卷积乘加数；新增参数、梯度和SGD动量存储，实际延迟仍未测量。参数增幅小不能证明40k足以收敛。

## 5. 反传改善的准确范围

令g_G、g_N表示两路主监督对投影参数的梯度，g_aux包括0.1辅助权重。共享时同一个参数接收g_G+g_N+g_aux；独立时P_G接收g_G+g_aux，P_N接收g_N。因此两尺度梯度不会在**投影同一个参数上**直接抵消。

这不意味着所有冲突消失：W48、Kc、分类器仍共享，P_G仍承受主/aux共同监督；全局裁剪还把所有参数梯度耦合在一起。拆分改变梯度范数、第一次更新和后续轨迹，不能以“初始预测一致”推出训练结果一致或更优。

仍采用全参数weight_decay=0.0005。P_N=P_G=W时，新投影正则项为λ(||W_G||²+||W_N||²)/2=λ||W||²，旧投影为λ||W||²/2，复制的affine同理。因此函数族包含只支持相同数据损失在全局最优处的inf关系，不支持本配方正则目标的同一不等式，更不支持有限40k SGD或验证离散mIoU的比较。没有为抵消此项另加LR、weight decay倍率或搜索分支。

## 6. 撤回“增加G才获得全局上下文”的论据

按本机实际timm W48源码中的stage数量，沿一条连续深层卷积路径，用r_new=r_old+(k−1)j_old、j_new=j_old×stride计算：

|路径节点|名义感受野边长|输入步距|
|---|---:|---:|
|两个stem卷积后|7|4|
|stage1后|39|4|
|stage2最深分支|175|8|
|stage3最深分支|1,215|16|
|stage4最深分支|2,783|32|

这是推理时一条卷积路径的名义支持范围，不是整个网络精确最大感受野，不计训练BN的跨位置统计耦合，也不意味着每个位置覆盖全部图像。它足以否定“原生2048路径因名义感受野太小而没有任何全局信息通道”的说法。

名义支持范围与真正对预测产生影响的有效感受野不同；这一概念区分有原始研究依据：[Understanding the Effective Receptive Field in Deep Convolutional Neural Networks](https://arxiv.org/abs/1701.04128)。本次不据此估算当前W48的有效感受野，也不推导收益百分点。

保留G的合理机制是让同一结构在不同表观尺度、边界密度和图像频率上提取特征，与N的细粒度路径在分类前共同使用。它是具体的结构动机；在当前数据上是否互补，尚未有该新模型的特征或预测证据。

## 7. 指标差距对应什么数学要求

固定同一验证标签，对某类令T=TP+FN，q为该类融合目标IoU；以NativePyramid v3固定40k计数为起点，δTP和δFP表示新模型的有符号变化，则：

~~~text
(TP+δTP)/(T+FP+δFP) > q
等价于 δTP − q·δFP > q(T+FP) − TP
~~~

|类别|目标q|右端所需净改善量|
|---|---:|---:|
|EX|0.5037020375|15,301.446|
|HE|0.4504046701|69,205.191|
|SE|0.5984178390|25,905.478|
|MA|0.2603487025|6,067.573|

这不是需要新增的固定TP数量：降低FP也按q贡献。逐类全部严格满足是超越目标均值的一条充分路线，不是必要条件；类别之间可以补偿。表格仅把目标转成可核查的错误计数关系，不以验证标签训练或调整预测。

目前的投影秩、函数族包含和感受野推导，都没有给出δTP或δFP的数值下界。要从结构论证推出“固定40k必超”，还缺少把本次初始化、数据顺序与优化过程连接到上述计数变化的证明。较低可达训练损失也不能直接补上这个环节：0.5阈值mIoU与平方Dice并非单调对应，v2审查已有具体反例。

## 8. 再次审查后的取舍

|审查问题|处理|
|---|---|
|两尺度是否在信息压缩前就被迫选相同方向？|拆分P_G/P_N；承认真实相关信息是否位于新增方向尚未确定|
|C/D可逆是否等于完整保留主干信息？|否；可逆起点是投影后的两个64通道张量|
|是否移除了旧方案能表达的预测？|可通过参数及缓冲区复制复现v2；不声称包含已训练v3或融合系统|
|是否用“相同初始输出”掩盖优化变化？|明确梯度分配、正则惩罚及全局裁剪均改变|
|是否靠增加通道数或模块堆叠预测收益？|不新增注意力、ASPP、RGB分支、更宽头或额外预测集成；缺少匹配证据|
|是否继续把全局信息缺失当作已证病因？|撤回；区分名义支持范围、有效感受野及尺度响应|
|是否增加训练预算或换预训练？|40k、physical/global batch2、指定ImageNet-W48、融合标签身份均不变|
|是否用旧计算图检查为新架构背书？|v2记录保留为历史；本次r3只完成结构代数与文档一致性复算|

成稿保留一套明确方案，不列多个候选让最后一次正式训练承担选择。**架构审查完成；性能目标仍未被证明或实测满足。** 这两个状态必须分别记录，不能将“未发现新的结构矛盾”写成“100%超过融合指标”。
