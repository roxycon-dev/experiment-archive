# HRDecoder 实现复审（2026-10-05）

范围：仅检查本地源码、validation 指标/审计 JSON 与报告；未 SSH、未启动训练/GPU、未改原档案，也未读取任何 test 概率或 test NPZ。下述结论区分源码错误、方案有意变化与待验证研究解释。

## 结论

1. **没有发现 DINO 接线、空间几何、概率加载/融合、FP32计数方面可解释低单模分数的实现错误。** 实际 Q 用官方 ViT-B/16、严格载入 LVD 权重；mean/std 匹配官方；层号、register token剥除、RoPE、共享 final norm 与 1024→中心768几何均正确。低单模结果应先视作表征/训练/校准问题，不因单模分数低就虚构工程 bug。
2. **F4/F12 参数组确实启用。** F4训练 blocks 8–11、backbone.norm 和 decoder/RGB；F12训练全12块、patch embed/CLS/register及 forward-active backbone参数和head。自定义 `set_update` 避免基础模型下一步重新冻结；AdamW只收集 `requires_grad` 参数；12k内每200步调度审计/保存。代码路径和 `trainable_parameter_groups.json`相互吻合。
3. **50%下滑能由公式和逐类结果解释，无证据指向错载/错位/精度bug。** 该式是 `0.50*P0+0.50*新Q`，不是递归混合R；新Q的单模每类都低于P0，MA尤其明显。50%权重减半了更强的P0，因此HE/SE/MA掉分；固定阈值0.5下的概率互补性/校准是合理假设，但本审查没有据此判定模型概率“错校准”。
4. **E_NEG改的是valid语义，不是标签栅格质量。** 用户已确认IDRiD多边形来自官方像素GT的无损转换；原转换器把完整性保守记为false，旧accepted manifest因此把28张SE已审阴性设为unknown/ignore。E_NEG manifest将其改为confirmed_negative，像素mask不变。E_NEG从u1就实际使用了新语义；u1600仅是RAM缓存/worker性能切换点。
5. **无配方可据现有两种子门槛晋级。** 报告明确候选0、无两种子完整终点、未运行新test227。下一轮首先要完成F12 checkpoint和val bundle的回收receipt/metrics核验；目前不把下载中的partial文件解释为损坏。

## 实现核验与相对成熟方案的变化

- `01`写第3/6/9/12层；`02`明确取索引`[2,5,8,11]`。Q调用官方 `get_intermediate_layers(...reshape=True,norm=True)`；官方循环在block索引2/5/8/11之后取特征，先用共享`norm`、再移除CLS+storage tokens并按patch网格reshape，1024输入得到64×64 patch图，故没有层号off-by-one或register错位（`01_成熟突破方案.md:L64-L70`; `02_执行与验收规范.md:L24`; `qlib/model.py:L31-L76`; `vendor/dinov3/dinov3/models/vision_transformer.py:L269-L316`）。官方ViT-B16确为4个storage/register tokens、RoPE按(H,W)动态生成；Q没有误用无关绝对位置嵌入（同文件`L112-L136,L190-L218,L229-L251`; `hub/backbones.py:L277-L310`）。
- 预训练不是随机初始化：按官方`dinov3_vitb16`结构建骨干，对权重SHA后`strict=True`载入；报告记录missing/unexpected均为空。RGB预处理是官方ImageNet mean/std；DPT层显式重建stride4/8/16/32，logits插值回1024后才裁中心768；halo/padding和回原图拼接与冻结的几何账本一致（`qlib/model.py:L79-L97`; `qlib/geometry.py:L6-L7,L59-L88`; vendored README `L258-L266`）。
- E_NEG core `model.py/geometry.py/loss.py/data.py/optim.py`与原Q源码SHA一致，性能加速路径仍按micro2×accum4、BF16、每有效更新一次clip/optimizer/scheduler；masked BCE+microbatch Dice在FP32，4个微批Dice再平均，正是`02`规定的语义而非全8样本global Dice。该损失和每更新4个前景+4个均匀窗会改变训练采样先验，所以固定0.5阈值及跨模型概率融合存在校准敏感性，属于研究风险（`performance.py:L79-L105`; `qlib/loss.py:L5-L23`; `qlib/data.py:L127-L181`; `02_执行与验收规范.md:L48,L60-L70`）。
- F4/F12不是原方案“先冻2k、继续原AdamW”的复刻：两臂从Q_DDR@16k模型权重开始，fresh AdamW，不载旧optimizer；新阶段12k、warmup200，head peak 5e-5，F4末四层渐进LR、F12另训patch/token参数，block11 peak 1e-5。协议已明示这是重热配对，只有F12−F4隔离解冻深度。E_NEG则沿用原Q的冻结/解冻、loss/optimizer/LR/采样，仅修正known-negative valid，并在u1600完整断点切换性能实现；不能把两种F臂和E_NEG当同一续训试验（`02:L68-L72`; `execution/configs/protocol.json:L20-L70`; `adaptation.py:L7-L78`; `train.py:L33-L52,L142-L160,L203-L227`; `qlib/optim.py:L21-L33`）。
- 3.55GiB/0.461秒不是只测冻结阶段：原Q预检明确100次unfrozen有效更新、峰值3.554GiB、unfrozen均速0.460821秒；新F预检中F4为3.56GiB/0.416秒，F12全骨干反传为6.48GiB/0.539秒（各100次有效更新），因此不能用F4数字代表F12显存（原报告`original_plan_experiment_result.json:L311-L323`; 新`reports/gpu_readiness.json:L65-L80,L859-L876`）。

## 下一轮Adapter式空间交互的决定性验收风险

本地官方DINOv3 segmentation `DINOv3_Adapter`把backbone全冻结（`dinov3_adapter.py:L325-L327`）；其`InteractionBlockWithCls`只有Extractor，更新空间流`c`后原样返回ViT tokens `x`（`L159-L231`），且前向对`get_intermediate_layers`套`no_grad`，只将既有ViT输出提取回空间流（`L408-L457`）。所以官方DINOv3 dense结果不能作为“早期SPM→ViT注入有效”的证据；这应是基于原ViT-Adapter交互设计的新假设。

若从F12@12k开发新臂，最关键的接口/门槛是：

1. 需要显式block循环在4处做patch-token注入/空间特征回提；官方`get_intermediate_layers`只返回已完成blocks的特征，无法在内部早注入。每次reshape只能切`CLS+4 registers`之后的patch序列，保持register tokens原位；RoPE仍按64×64网格传给后续每个官方block。不要另加绝对位置编码。
2. SPM用GN，产出stride4/8/16/32特征，与旧DPT四个128通道输入严格同shape后相加；原RGB支路、DPT、输出1024/中心768几何先保持不变。新臂的checkpoint身份要锚定已验收F12 SHA，新增参数单独列组；配一个同F12起点、同DDR窗口/step/优化器与评估的DDR-only续训控制。
3. 用一个新支路投影零初始化保证0步logits/概率与F12恒等；每条新增输出仅一处zero projection，避免连续零门控导致死梯度。梯度验收需分两步：第0步该零投影获得非零有限梯度；第1步更新后SPM/Injector/Extractor上游应出现梯度且参数变化；否则定位detach/no_grad、token分片、shape或优化器参数漏组。首次100%旧输出等价、各尺度shape、非有限值、checkpoint roundtrip都通过后，再考虑正式seed对照。
