## 4. 资料冲突与缺口（并列，不裁决）

1. **冠军数值口径**：早期审查报告把冠军 test 写作 44.21；FullCompetition/FusionAware 使用精确 44.2115，四舍五入后一致。FullCompetition champion val 0.4266942845，FusionAware 报告常写 0.4267，属精度层级差异。
2. **冠军组成文字**：部分报告写“D×3+E×2+B+E4 + 翻转 TTA + H4 MA 头”，FullCompetition 资产审计要求用 `full_eval_settings.json`/`RUN_PLAN.json` 的成员和 SHA；互补性报告另把 `champion` 与 `BASE_0` 做逐位比较。成员身份应以各自 settings/contract 字段展开，不能只按简称合并。
3. **同名 U0**：审查轮计划的 U0 是未执行的 HRPlus 结构；FullCompetition `runs` 的 U0 是已完成的 ConvNeXt-UNet 12k 训练。两者必须保留 family、目录、config hash。
4. **C/S 指标精度**：C/S 正式报告四舍五入到 4 位百分数，remote recovery 的 `*_summary.json` 有更高精度；CSV 同时保留 summary 原值和报告展示值。
5. **BASE0/D_BLEND 小数冲突**：leaderboard 与 mask 重算差 1.05e-5 / 5.4e-7；互补性执行报告称为 variant A/B 差异，未改写 leaderboard。
6. **E4/H4 完整证据缺口**：H4 本地只有小 `.pth` 和结果 JSON，完整服务器 checkpoint、E/L/D 原始训练日志在 `missing_dependencies.md` 仍列 BLOCKED；不能把结果 JSON 自动视为完整身份验证。
7. **历史 baseline 与新 run**：42.20、39.39 是历史报告/日志对照，`autodl100` 没有重训 baseline；FullCompetition U0 不是 baseline 复跑，不能用 38.4464 替代 39.39/42.20。
8. **test/val 口径混用风险**：`e2e3_tuned_test_final.json` 的逐类阈值 test 平均 0.4086，`e4v2_test_final.json` 固定阈值平均 0.4006；后续 42.xx/44.xx 主表固定 0.5、四类累计 IoU。两类 JSON 必须分组保存。
9. **空/失败输出**：MA 目录多个 smoke JSON 为 0 bytes；FusionAware 多个 pulled 状态目录的 lock/report 为空；FullCompetition 互补性轮保留 `hrplus_exit_code.txt=2` 历史失败文件并另行补写 contract。它们是失败/空输出事实，不应填成零分或成功。
10. **计划与执行**：审查轮 RUN_PLAN 仍有 T0/T1/U0/E1/V1/J0/J1/C1/F1 NOT_RUN；FusionAware 计划文档也有“若过门才 test”的条件分支。只有带日志、状态、summary、计数或回收 manifest 的项列为执行事实。
11. **统计/独立性缺口**：资料多次记载 test 已被查看（FullCompetition 互补性报告写“≥5 次”）；本核查不把 test 作为独立留出验证，也不裁决其统计意义。
