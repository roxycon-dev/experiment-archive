## 第 0 章 一句话总览（先看这个）

这个项目做的事情是：**用 HRDecoder 网络在 DDR 眼底照片上分割 4 种糖尿病视网膜病变（出血斑 EX、出血 HE、硬性渗出 SE、微动脉瘤 MA），指标是 4 类平均 IoU（mIoU）**。历史上第一轮的 baseline 拿到了 test mIoU **42.20**，之后两轮共十几次改进尝试（换损失、加模块、加增强）**全部失败**。2026-09-10 一个 AI 做了纯静态诊断，指出"失败原因根本没被干净定位，报告里还有多处数字/引用错误"，并押注两个方向；2026-09-11~12 另一个 AI 拿着 100 元预算上 AutoDL 4090 做最后一轮实验：新分支（方案 A）失败、对照组（方案 B）差一点、按类别拼模型（阶段 2）失败，最后用**两个老模型概率固定对半平均**拿到 test **42.35**，比 baseline 高 **0.15 个百分点**——数值上达标，但报告自己诚实地承认：这只是"集成带来的有限收益"，不是什么被证明的机制性突破，也不足以支撑论文创新。

下面把每个名词、每一步原理、每个数字为什么是这样，全部展开讲清楚。

## 第 1 章 任务与数据的完整背景

### 1.1 分割的对象是什么

DDR（Diabetic Retinopathy Database）是眼底相机拍的眼睛内部照片。任务是在一张照片上给 4 类病灶逐个像素分类：

| 类别编号（标签值） | 通道编号（logits 顺序） | 缩写 | 中文 | 外观 |
|---|---|---|---|---|
| 0 | — | bg | 背景 | 不算分 |
| 1 | 0 | EX | 硬性渗出 | 黄白色亮斑，中等大小 |
| 2 | 1 | HE | 出血 | 暗红色大块 |
| 3 | 2 | SE | 软性渗出（棉绒斑） | 白色羽状大片 |
| 4 | 3 | MA | 微动脉瘤 | 极小的暗红圆点 |

关键事实：**MA 是最难也最便宜的"提分空间"**。4 类里 MA 的 IoU 只有 24 左右，其余三类都在 42~52。因为 mIoU 是四类**等权平均**（每类占 1/4），MA 每涨 4 个百分点、总分才涨 1 个百分点——这是诊断报告反复用来泼冷水的算术事实。

### 1.2 多标签 sigmoid 分割，而不是普通 softmax 分割

普通语义分割假设每个像素只属于一类，网络输出一组互相竞争的 logits 再 softmax。病灶不一样：**一个像素可能同时是 MA 又是别的，而且四类各自是"有没有"的独立判断**。所以本仓库（HRDecoder 官方代码）把任务改成了：

- 网络头输出 4 个独立通道，每个通道过 **sigmoid** 变成该类的"概率图"；
- 损失是 4 个独立的二分类 Dice 之和除以 4（`binary_loss.py` 第 99~115 行：对每个类调一次 `binary_dice_loss`，`loss = loss / num_classes`）；
- 评估时每个类各算一个"全数据集累计 IoU"：把所有测试图的该类的 TP、FP、FN 直接加总，`IoU = TP / (GT + FP)`（等价写法），再对 4 类取平均 = mIoU。

注意"累计"二字：这不是"每张图算 IoU 再平均"。一张没有任何 SE 的图不会贡献分母；像素多的大病灶天然占更大权重。诊断报告确认这套公式本身没有错误（证据等级 B），十个百分点的差距不可能用分母写错来解释。

### 1.3 数据划分：757 张图怎么分成 454/76/227

DDR 官方给的分割训练协议是 383 训练 / 149 验证 / 225 测试。本项目用了**自定义划分 454/76/227**（目录名 DDR_split_613 的"613"来自 6:1:3 的抽样比例）。划分脚本只按 **SE 是否存在**做了分层（`bundle/split_assignment.json` 里每张图有 `tier` 字段 A/B/C，记录图片来源子集与病灶像素数），核对结果：

- train 454 / val 76 / test 227，与全部报告一致；
- SE 阳性图：train 143 / val 24 / test 72；
- 打包传输清单共 **1514 个文件**（757 图 + 757 标签 png），断点续传后逐文件 SHA256 全部校验通过。

这个划分的三个隐患（诊断报告指出，100 元实验也反复强调）：

1. **验证集只有 76 张**。SE 阳性仅约 24 张，一类病灶少几十个百分点的 IoU 可能就来自几张大图。后面你会看到"76 张验证集选模"如何精确地坑死了阶段 2。
2. **四类联合分布没平衡**：EX 像素占比 train/val/test = 0.2466% / 0.0728% / 0.1337%，train 的 EX 密度约为 val 的 3.4 倍，验证集根本代表不了测试集在该类上的表现。
3. **同一患者/双眼/近重复照片是否跨集合，没有任何分组约束证明过**。诊断报告把这条列为等级 D（未核实），明确说"不能写成已发现泄漏，但必须列为待核查的独立性问题"。
4. 另外划分被 test 反复参与选路之后，它已不是"干净的外部测试集"，只能当内部基准（详见 5.4）。

### 1.4 图像尺寸与预处理

原始 tif 尺寸不统一（实测抽读有 2592×1728、1956×1934 等）。数据管线（`hr_ddr_2048.py`）统一：训练时随机缩放（ratio 0.5~2.0）→ 2048×2048 随机裁剪 → 翻转 → ±45° 旋转 → 按 DDR 统计量归一化（mean [81.2, 50.6, 21.2]，std [76.3, 48.8, 21.6]）。测试时整图 resize 到 2048×2048，**无翻转无 TTA**。

"统一到 2048²"这个事实后面会用来纠正一份报告的单位错误（第 4.6 节）。

## 第 2 章 HRDecoder 模型原理：它到底在干什么

这是理解一切争论的地基，讲慢一点。

### 2.1 HRNet 主干 + "假装看到高清"

HRDecoder 是 2024 年 MICCAI 论文，动机是"高分辨率输入很贵，但小病灶需要高分辨率"。它的做法（对应代码 `HRDecoder.py`，全仓库哈希 81D775…D073C）：

**主干只见过 1024×1024。** `encode_decode` 第一行 `lr_img = resize(img, self.hr_scale)`，其中 `hr_scale=(1024,1024)`（配置 `baseline_split613.py` 第 18 行）。也就是说测试图虽然 resize 到 2048² 进来，**主干 HRNet 实际只看到一半分辨率**，输出一张 1024 空间尺度、720 通道的特征图（HRNet 4 个分辨率分支的 48+96+192+384 通道对齐拼接，`_transform_inputs`）。

**"高分辨率分支"是裁特征块再插值。** 训练时（`hr_forward_train`）：在 2048² 的标签图上随机取 `crop_num=4` 个约 1024 大小的窗口，在 720 通道特征图上找对应的小区域裁出来，再 `resize` 回 1024² 送进同一个 decode head（`_resizecrop_feats`：`lr_crop_feat = crop(feat, lr_bbox); hr_feat = resize(lr_crop_feat, feat.shape[2:])`）。因为裁的是特征图的一小块、又拉回全尺寸，**等效于在局部"放大看"**——但请注意，放大的全部信息都来自那张 1024² 输入，**没有任何新的原始像素进入主干**。这就是"模拟高分辨率（simulated HR）"。

**融合是写死的对半平均。** `_fuse_logits` 默认分支 `(hr_logit + lr_logit) / 2`；整图 logits 双线性上采样到 2048² 后，与每个滑动窗口块的 HR logits 在重叠区域按固定 0.5/0.5 混合。论文原文明确说这是设计（还做过注意力融合对照并选择了简单方案）。

推理时（`hr_slide_inference`）以 stride=hr_scale 的规则窗口铺满整图，逐块解码，再按块边界写回融合。

**一句话理解这个架构的赌注**：只要 decode head（FCN，kernel=7 的大卷积 + 1 个 3×3，channels=64）足够强，从低分辨率特征里"插值 + 再加工"就能恢复出小病灶的定位。赌注的代价是：主干没看过的高频细节（比如一个 2~3 像素宽的暗点），插值是变不出来的——"信息在 downsample 时被抹掉"假说的来源。

### 2.2 Efficient 变体

代码里还有 `EfficientHRDecoder`：在 720 通道拼接后加一个 1×1 压缩到 256 通道再送 head，省显存用的。100 元实验用的 A/B 模型沿用 HRDecoder 原路（720 通道全量进语义分支），因为微调起点是 E4 权重。

### 2.3 为什么这套结构值得被"诊断"

第一轮 baseline 的 per-class test IoU（历史报告，经 100 元实验复核一致）：EX ~50 / HE ~42 / SE 49.98 / MA 24.11。SE 其实是最容易的（IoU 已经 50，因为它面积大、像素多），MA 是最差的。历史两轮实验对"为什么差"的解释不断在"分辨率丢信息"与"类别不平衡"之间摇摆——这正是诊断报告开火的地方：它认为**真正的原因根本没被隔离出来**。

## 第 3 章 第一轮实验（2026-08 中旬，week1）：baseline 与 SE 增强

### 3.1 发生了什么（据历史报告与代码）

- baseline：HRDecoder + 自定义 613 划分 + batch=2、SGD lr=0.005、40k iter、seed=42、每 4000 iter 验证。val 曲线最高点 39.39@32k；**test mIoU 42.20**。
- 板块二：针对"SE 稀少"做 copy-paste 增强（从训练集里裁 SE 矩形块贴到别的眼底图上），外加 SE 专属采样/像素逆频率加权。结果是负的。

### 3.2 诊断报告抓到的确定性 bug：copy-paste 的图像与标签合成不一致（证据等级 A）

这是全部诊断里最硬的一条，值得完全吃透。看 `02_板块二_增强实现_se_aug.py` 第 109~111 行：

```python
img[y:y+ph, x:x+pw] = pimg                      # 图像：整个矩形块覆盖
gt[y:y+ph, x:x+pw] = np.maximum(gt[...], pmask) # 标签：逐像素取最大值
```

而病灶库（`build_se_library.py`）只保存了 **SE 通道**的掩膜（`crop_mask = se_mask[y0:y1,x0:x1] * 3`）。于是三种污染必然发生：

1. **盖掉病灶、标签残留**：目标图原处有一个 HE（标签 2），来源 SE 矩形（标签 3，SE=3>HE=2）整个盖上去——HE 的像素被抹掉了，但 `maximum` 之后标签还是 3，模型被教"这片新像素是 SE"。反过来若来源该处是背景（0），旧标签 2 又会被 maximum 保留——**图上没了病灶，标签还说有**。
2. **带入无标签外观**：来源矩形里除了 SE 还可能夹着 MA/HE/EX 的像素，但库里根本没保存它们的标签，贴过来之后这些外观对应着"背景"。
3. **类别编号大小决定语义**：`maximum` 的本质是"谁编号大听谁的"，而编号 1<2<3<4 只是命名顺序，跟"遮挡关系"毫无逻辑。整张图等于随机重排标签优先级。

诊断报告的结论措辞非常克制，值得学习：这个 bug **确定存在**，所以"第一轮 SE copy-paste 失败证明医学 copy-paste 泛化差"这个因果归因要**撤销**（实验条件被污染了，不算干净验证）；但**修复它就一定能超过 baseline 吗？没有信心**——因为 SE 本来 IoU 就最高、最值得改的也不是它，而且受污染像素的实际频率没人统计过。**"撤销一个错误结论"≠"反过来就成立"**，这是这两份报告共同的方法论底色。

### 3.3 第一轮的因果链错在哪

原报告说"SE 稀少 → 像素逆频率加权合理 → 失败 → 增强无效"。诊断指出：逐类 Dice 已经是对 4 类求平均的，等于每类自带归一化；单纯像素占比加权会**再次扭曲任务权衡**，而且"SE 稀少"和"SE 最值得提升"是两码事（SE IoU 49.98 已经最高）。梯度到底被谁支配，取决于分母、空标签图、置信度、共享参数，原报告一项都没测。

## 第 4 章 第二轮实验（2026-08 下旬，week2）：E1~E4 全记录

这一轮转向了 MA：换损失、学融合、加上下文、加细节分支。全部 6 个主要配置的真实成绩（数字来源：逐行 JSON 训练日志 + 测试加载路径互证，诊断报告重读日志后重制；原始 `验证轨迹.csv`、`最佳点核对.csv`、`关键测试记录.txt` 与 100 元实验日志全部复核一致）：

| 配置 | 干预内容 | 最佳 val mIoU（真实） | 加载 checkpoint | test mIoU |
|---|---|---|---|---|
| baseline | 无 | 39.39 | 32k | **42.20** |
| Tversky (E1) | Dice→Tversky（α=0.3 / 0.7 两次） | 4k 即全正预测崩溃、被停 | — | 未测 |
| CE+Dice (E1v2) | Dice→CE+Dice | 39.97 | 12k | 39.43 |
| E2 | LR/HR 融合权重改为可学习（每类一个 softmax 标量） | （并入下行） | — | — |
| E2+E3 | 可学习融合 + FCN 头里加 ASPP-lite 上下文 | 39.21 | 20k | 39.98（调阈值后 40.86） |
| E4 | 原图浅层细节分支 + 零初始化标量门控相加 | 38.77 | **36k**（报告原写 24k，错） | 41.63 |
| E4v2 | E4 + 细节路径直接受 0.3 权重辅助损失 | 38.67 | **36k**（报告原写 32k，错） | 40.06 |
| E4+CE+Dice (combo) | 组合 | 39.87 | 32k | 41.08 |

几个必须看懂的机制：

### 4.1 E4 细节分支长什么样

`DetailBranch`（`detail_branch.py`）：原始 2048² 图像过三层 3×3 卷积（stride 2、2、1）→ 1/4 分辨率 32 通道特征 → `DetailHead` 两层 3×3 + 1×1 分类 → 4 通道 logits → 上采样回 2048²。然后：

```python
fuse_logit = fuse_logit + self.detail_scale * detail_logit   # detail_scale 初始化为 0
```

设计意图（配置注释原话）：MA 中位数面积极小，1024 主干的 stride-4 网格里一个格子盖不住一个 MA，所以让一个"真的看过原图"的浅层分支把细节加回来。零初始化门控让训练起点严格等于 baseline。

### 4.2 E4 的效果：只换来了工作点移动，没换来 IoU

E4 的 MA：召回 33.54% → ~39.3%，精度 46.17% → ~38.4%，IoU 24.11 → 24.13（几乎不动）。诊断报告用这组数字做了全项目最核心的因果分析之一：**"多预测出一些小暗点"（召回↑）被"同时多预测出更多假阳性"（精度↓）精确抵消**。它可能只是把操作点往右推（同样阈值下更敢报），而非"恢复了主干丢失的信息"。要证明后者需要同召回水平下的精度对照或完整 PR 曲线——历史报告没有提供。

### 4.3 零门控的梯度问题（一个精细的辨析）

`detail_scale=0` 时，细节头参数的梯度 = s·(∂L/∂z)·(∂dθ/∂θ) = **0**：起步第一步细节分支从主损失拿不到任何梯度；但 s 自身有梯度（∂L/∂s = dθ·∂L/∂z ≠ 0），所以 s 一旦离开 0，细节分支就开始学习。**不是永久断梯度。** 日志里 1k 步 s≈0.00077 说明它确实在学，诊断报告明确禁止"早期 s 小 = 全程没学到"和"只看 s 判断贡献大小"两种误读（要看 s 还要看 dθ 幅值和梯度）。E4v2 给辅助损失后仍然没赢，也只说明"这套浅分支+0.3 权重"不够，不证明"所有辅助任务都会干扰"。

### 4.4 验证曲线的剧烈震荡——比任何单个失败都重要的线索

从 JSON 日志直接读出的 val 曲线（`验证轨迹.csv`）：

- baseline：16k 38.35 → **20k 32.52**（跌 5.8 个点）→ 24k 36.19 → 32k 39.39；
- E4：16k 38.18 → **20k 31.89** → 24k 38.03；
- E2E3：20k 39.21 → **24k 33.06**；
- CE+Dice：4k 31.16 → 12k **39.97**（此后回落震荡）。

固定验证集上不可能出现"抽样噪声"式的这种跌落——说明是**训练侧**的问题：优化状态、BN 运行统计或数据序列。诊断报告据此提出全项目最重要的工程怀疑（等级 C，"可检验假说"而非定论）：**batch=2 + backbone BN 持续更新（norm_eval=False）+ 同一个共享 decoder 在训练中先后处理"整图特征 / 随机尺度裁块 / 规则裁块"三种统计分布完全不同的输入**——推理时用的是被三种分布混合污染的运行均值。小 batch 放大每批内容差异。但报告同样克制：很多模型 batch=2 训得好好的，原架构也共享 decoder，所以"不能仅凭配置宣布 BN 是根本原因"，只能列为"值得低成本优先验证"。

100 元实验正是把"冻结 BN"作为微调协议的一部分直接上了（见 5.2），且阶段 1 的震荡仍然存在——说明 BN 至少不是唯一原因。

### 4.5 Tversky 崩溃与一个被撤回的引用

`binary_dice_loss` 分母是 `Σp²+Σy²`（平方 Dice，对置信度敏感），`tversky_loss` 分母是 `TP + α·FN + β·FP`。诊断报告纠正原报告的归因："Dice 分子多 2TP 所以背景梯度强一倍"**不是通用成立**的论证（α=β=0.5 的 Tversky 与标准线性 Dice 在相应平滑约定下等价）。更合理的怀疑是：极稀疏前景 + 逐图逐类比值 + 空标签裁块 + smooth=1e-5 的联合作用——空标签图的 Dice/Tversky 对负样本的梯度可能极弱，而 BCE（CE 路线）有直接的逐像素监督。这解释了为什么 CE+Dice 能训动而 Tversky 4k 步就塌成全正。

**引用事故**：原调研用 Andersen 等（MIDL 2020）佐证"Tversky 对 MA 有效"，而原文实际报告的是 CE 类损失在 MA 分割/检测上优于 Dice 与 Focal Tversky、且 Focal Tversky 检不出 MA——方向完全反了。诊断报告明确"撤回该引用"。这条对后面选 B 方案的"保留 BCE 式逐像素监督"有直接支撑作用。

### 4.6 分辨率证据链里的单位错误（为什么"MA 比格子还小"不能直接推）

原分析声称"MA 中位面积 48px²、主干 stride-4 网格 64px²，所以多数 MA 装不进一个网格"。诊断核查 `dataset_stats.py`：连通域统计**直接做在原始 tif 上**（2592×1728、1956×1934 等混在一起），没有统一到 2048²。一张 W×H 原图的 48px² 病灶缩到 2048² 再进 1024 主干，面积是 `48 × (1024²)/(WH)` 量级的换算，**逐图尺寸不同、换算就不同**，不能拿混合分辨率的中位数直接除以 64。该结论**撤回**。

另外检出统计脚本以"有一个预测像素重叠"算检出，不衡量假阳性和勾画质量；分桶边界（上界不含）漏掉了 9、49、99、499 px 这几个桶。结论：这些分析可以当线索，不能当"分辨率是唯一主因"的证明。而 EX 中位面积 56 与 MA 的 48 接近、IoU 却差一倍以上，直接提示**外观对比度、形态与分类混淆**至少同样重要。

### 4.7 AUPR 端点问题与阈值校准的真实边界

`e6_threshold_analysis.py`：粗网格 `linspace(0,1,11)` 含端点 0 和 1；细网格 `linspace(0.01,0.99,99)` 不含——两者的 PR 曲线召回覆盖范围可能不同，所以"57.1 vs 43.0 全是粗网格高估"不成立。**注意**：这只影响 AUPR 的解释，不影响 IoU 主指标。

逐类阈值调优（把每个类的判决阈值从 0.5 挪到最优）：E2E3 从 39.98 → 40.86（+0.88），E4 41.63 → 41.61（无效）。诊断警告：**+0.88 是 E2E3 这个弱模型在测试集上调出来的，baseline 本身能调出多少从没测过**，所以"阈值校准是唯一正收益"的强结论撤回。阈值只移动工作点、不改善排序能力，它永远可以被当作给所有模型的公平后处理，但论文里必须与网络改进分开标注。

### 4.8 诊断报告对 42.20 本身地位的定性

42.20 是**内部基准**，不是论文复现达标证明：官方 README DDR mIoU 32.24 / 论文 32.25（三次重复），你们的 42.20 高 10 个点是因为**划分、训练量、batch 全不同**（官方 383/149/225、batch=4、40k=160k 图次；你们 454/76/227、batch=2、40k=80k 图次），且选点在自定义 val 上。第一轮那次官方划分 run（30.81）是 `val=test` 选点的，不能当严格复现认证。——所以 42.20 既不用妄自菲薄也不用当成超过论文的证据，它就是一个"同协议同划分下你要打败的内部对手"。

### 4.9 诊断报告给出的两条路（100 元实验的设计蓝本）

1. **优先级一：先把对照做可信**。最小干预：只把 decode head 的 BN 换成 GN（主干 HRNet 预训练 BN 保留），验证多尺度共享头 + 小 batch 的统计混合假说；或成本更低的"用已有 checkpoint + 训练集重估 BN 运行统计再评"。
2. **优先级二（唯一的押注）：语义条件下的 MA 残差修正**。E4 已经证明"无脑加细节"不行，所以新方案必须满足：细节分支**分类前**拿到主干语义（原图细节特征 + 对齐的粗语义特征 + 基准 MA 分数 → MA 残差），**只改 MA 通道**（其他三类由构造保证不降），零初始化，冻结成熟基准网络只训修正头，新头用 GN，难负例只能来自训练集，推理覆盖整图而非只在 baseline 阳性候选区 refine。
   判定标准同样苛刻：MA IoU 上升，且**同召回下精度改善**，新增真阳性不被 FP 抵消；只有召回上涨不算数。

两份报告最不利证据也被如实列出：HRDecoder 自己论文的对照里，真·高分辨率双路 HRDA 在 DDR 上 32.32 vs HRDecoder 32.25——"只要输入更高清就涨很多"被压了信心。所以全部期望只给"中等置信度"。

## 第 5 章 100 元收尾实验全程（autodl100，2026-09-11~12）

这是把上面的诊断变成真金白银实验的最后一次尝试。预算、纪律、每一步的动机都写在 5 份 md 和一堆锁定 JSON 里，我按时间线把原理全部展开。

### 5.0 预算纪律（执行方案.md）

- 总预算 100 元，RTX 4090 单卡 1.98 元/小时，**所有实例累计最多 45 卡时**；阶段 1 每台最多 10 小时、最多两台（上限 39.60 元），余款留安全边际；
- 每次开机前在平台设置**绝对关机时间**，训练进程退出/超时后还要独立关机；"SSH 断开不能作为停机证明，必须在控制台确认已关机"——预算不能依赖 AI 助手一直在线；
- 选模只用 76 张 val；test 只用于最终已锁定方案；主指标固定阈值 0.5、四类累计 IoU 平均；**禁止挑有利类别替代 mIoU；阈值优化、TTA 必须另行标注**；
- 明确不承诺超越 42.20，承诺的是：实际验证、保留失败结果、严格同协议、守预算。

最后一条也提前写了：历史 baseline 不重训（找回官方权重优先，但官方权重不能排除训练过你们的 test，故不用于自定义划分初始化）。

### 5.1 方案 A / B 设计（执行方案.md + 实施记录.md）

找到旧 E4@36000 权重（`e4_reference_weights.pth`，checkpoint 内 `best_score=0.38766`，与历史日志互证）作为两个方案的**共同微调起点**：

- **方案 A = 语义条件 MA 残差分支**（诊断优先级二的落地）：原图浅层细节特征（stride-2→2 卷积，3→16→32 通道）与 **720 通道主干语义特征经 1×1 压缩**对齐拼接 → 两层 GroupNorm(8) 3×3 卷积 → 1×1 输出 1 通道 MA 残差 → **末层权重和偏置全部零初始化** → 只加到 logits 的 MA 通道（`refine_logits` 里 `torch.cat([logits[:,:3], ma], 1)`）。新增监督：权重 0.02 的 MA 正像素/难负样本软标签损失。
- **方案 B = 无分支对照**：E4 原结构不动，只加同样的 MA 辅助损失。A/B 共同变化：SGD lr 5e-4（baseline 的 1/10）、poly 衰减 + 200 步 warmup、梯度裁剪 5、**冻结全部 BN**（`train()` 覆写里把所有 `_BatchNorm` 设为 eval，运行统计保持预训练值）、8000 步、每 1000 步验证、seed 42。
  设计动机写得很清楚：B 与 A 形成"有解释力的对照"——如果 A 赢，赢的是语义分支；如果 B 也赢，说明赢的是微调协议而非新模块。

### 5.2 训练前的本地验证（实施记录.md）

正式上卡之前做了 5 项单元验证：残差初始为零、MA 辅助损失只作用于 MA 通道、ignore_index=255 行为、标签不被修改、语义分支更新后梯度非零。服务器 3 步真实训练冒烟（显存 18982MB，0.53 秒/步）。这些防止了 E4 那种"训练 4k 步才发现方向错"的浪费。

### 5.3 阶段 1 结果：A 失败，B 没到线

| 方案 | 8000 步 val 曲线要点 | 结论 |
|---|---|---|
| A | **38.632@1000 即最佳**，随后单调下滑至 38.265 | 从未超过 E4 起点 38.766 → 不追加预算、不看 test |
| B | **39.205@3000 最佳**，其后回落（37.45~38.6 震荡） | 超过 E4 起点 +0.44pp，但低于历史 baseline val 39.39 |

A 的失败模式值得注意：**第一步之后就没赢过**。零初始化意味着起步严格等于起点，1000 步达到峰值说明残差分支早期有一点用，随后低 lr 微调把它带偏/过拟合了——修正头本身训练预算与冻结策略的矛盾。诊断报告当初预警过这种可能。

B 按协议锁定 @3000 权重跑 test（test_selection_lock.json 先落盘再看 test）：**EX 52.65 / HE 44.37 / SE 48.91 / MA 21.74，mIoU 41.92**。超过 E4 的 41.63，**没超过 baseline 42.20**。

**关键归因**（阶段2_判断.md）：B 的 val 相对 E4 的变化是 EX 43.30→44.25、SE 48.03→51.62，而 **MA 20.95→19.40（下降）**，MA 召回 37.34→27.78、精度 32.31→39.14——0.02 的 MA 难负样本监督只压出了精度、把召回压没了，IoU 反降。**B 的增益全部来自 EX/SE，与 MA 机制无关；A 的语义分支也没兑现。** 于是停止 A，转向"模型互补性"。

### 5.4 阶段 2：按类别路由的失败——76 张验证集如何精确坑人

思路：两个模型（E4、B）独立推理、输出各自 4 通道概率，**每个类别挑验证 IoU 更高的那个模型的通道**。依据预先保存的验证表（ensemble_selection_lock.json）：

| 类别 | val E4 | val B | 路由选择 |
|---|---|---|---|
| EX | 43.30 | 44.25 | B |
| HE | **42.79** | 41.55 | E4 |
| SE | 48.03 | **51.62** | B |
| MA | **20.95** | 19.40 | E4 |

预期 val = (44.25+42.79+51.62+20.95)/4 = **39.90**，实测 39.90（实现正确性被验证）。然后看 test：

| 类别 | test E4 | test B | 路由实际取到 | 问题 |
|---|---|---|---|---|
| EX | 50.93 | 52.65 | B ✓ | |
| HE | 41.61 | **44.37** | E4 ✗ | **排名在 test 上反了** |
| SE | 49.84 | 48.91 | B ✓ | |
| MA | 24.13 | 21.74 | E4 ✓ | |

实测 test = (52.65+41.61+48.91+24.13)/4 = **41.82**，低于 B 单模型 41.92，更低于 42.20。**HE 一类的验证排名不迁移到测试，把 2.76 个点的类别收益变成了损失。** 这就是"76 张验证集上的逐类选模不稳定"的教科书式实锤。

实施记录里写明了纪律："**禁止据此测试结果再改类别路由去凑目标**"——他们真的没改。这条纪律在 5.5 直接兑现成了价值。

### 5.5 阶段 3：固定 50/50 概率平均——唯一过线的方案

从失败里学的教训是"减少选择自由度"。最终方案（`hr100_ensemble.py` 的 `HR100MeanEnsemble`）：两个模型各自推理到原图尺寸、各自 sigmoid 成概率，然后 `(p_E4 + p_B) / 2`，**每个像素、每个类别权重完全相同（0.5/0.5）**，阈值 0.5、无 TTA。

事前锁定文件（mean_ensemble_lock.json，2026-09-11 19:38 UTC 落盘）写死：组合=算术平均、权重 0.5 全类相同、只用验证 76 张选、**过门条件 val mIoU > 39.40 才允许考虑一次锁定的 test**、no_grid_search（不搜混合比例、不搜类别权重）。19:45 val=39.54 过门，test 被授权；19:52 结束。

结果：**val 39.54 / test 42.35**（EX 52.29 / HE 43.95 / SE 49.93 / MA 23.22）。相对 42.20：**+0.15pp**。

**为什么等权平均赢了逐类路由？** 直观解释：等权平均是对"两模型分歧"的**整体正则化**——每个像素上两模型都同意的地方保留，分歧处被平均稀释后多数仍过/不过 0.5，收益来自互补而不需要"哪个类哪个模型好"这种高自由度统计（后者在 76 张图上不可估）。MA 的教训也在：平均后 MA IoU 23.22 介于两模型之间（E4 24.13 / B 21.74 之间偏 E4），说明它没有毁掉 E4 的 MA 优势，同时吃到了 B 在 EX/SE 上的增益。

### 5.6 最终结论报告自己怎么定性（这份诚实是全套材料最有价值的部分）

最终实验结论.md 的要点，逐条翻译成人话：

1. **+0.15pp 不是已证明的改进**。没有重跑 baseline、没有多种子、没有配对置信区间、同 test 被反复看过（探索性结果）。论文里不能把它写成"新方法显著超越 baseline"。
2. **本轮不支持"再加一个 MA 细节模块就会涨"**——A 失败、B 赢在别处，与诊断报告"机制性收益未被证明"的预判一致。
3. 集成需要两个模型前向，**部署成本翻倍**，论文必须公平报告。
4. 若还要继续：先做独立留出验证这 0.15pp 是否稳定，再研究"冻结主体的病灶专项残差"以减少类别间退步；当前不继续开机、不根据 test 调参。
5. 复现链完整：权重哈希、配置入口（`hr100_mean_release.py`）、锁定文件、失败日志全部保留；唯一坑是 `compute_aupr` 必须保持 True（见 5.8）。

### 5.8 工程事故簿（每件事都留下了可复用的教训）

1. **compute_aupr=False 触发旧代码形状 bug**：旧版 `simple_test` 在关闭 AUPR 时返回 4×H×W 裸数组，`single_gpu_test` 的 `extend` 把"一张图的 4 个通道"当成"4 个样本"——进度条变成 304/76、IoU>100%。无效日志被保留但**不用于选模**。教训：老框架的返回契约变了会静默毁掉评估；协议字段（与历史一致 compute_aupr=True）不可随手关。
2. **自动关机失败**：镜像里 `/usr/bin/shutdown` 直接 Popen 报 `OSError: Exec format error`（该脚本需 bash 解释器）。阶段 1 的关机被迫在 AutoDL 控制台手动完成。修复：包装程序改为 `/bin/bash /usr/bin/shutdown`，后续会话自动关机成功并经控制台复核。教训：任何"停机保险"必须端到端真实验证，dry-run 成功 ≠ 真关机成功。
3. **GLM 看门狗委托**：让 GLM-5.3 写"带绝对 deadline + 无论成败都关机"的训练包装脚本，第一次限流、第二次推理 token 耗尽无正文，降 reasoning_effort 后成功；**草稿本身有缺陷**（重复 setsid、不能保证"启动失败也关机"），人工审查重写后用 dry-run 验证了成功/非零退出/超时/无法启动四条路径。看门狗 + 平台定时 + 本地监控 automation 三层保险（automationId hrdecoder-100，每 30 分钟检查，完成后暂停）。
4. **备份传输**：SFTP 预读取卡死 → 改 SSH 流式传回 weights-only checkpoint（A 263,709,987 B / B 263,479,238 B，本地哈希记录在 backup_verified.json）。
5. **数据完整性**：分块续传后 1514 文件逐个 SHA256 校验通过，才允许开训。

## 第 6 章 把整件事串起来：三层"谁在纠正谁"

这套目录的独特结构是：**每一层 AI 都在审计上一层，并且审计本身也被审计**。

```
第 1 层（2026-08 实验 AI）：做实验，写报告 → 产出 baseline 42.20 与 E1~E4 全部负结果
        ↓ 报告里有：copy-paste bug 未察觉、CE+Dice/E4/E4v2 的 val 与迭代数写错、
          MA 面积单位错误、AUPR 对比方法学错误、引用方向反了、过度自信的因果叙事
第 2 层（2026-09-10 诊断 AI）：只读静态审计（代码+日志+文献），不改实验
        产出：证据分级 A/B/C/D；纠错表；两个押注方向；"失败原因未被干净定位"的总判断
        ↓ 100 元实验按它的优先级二设计 A，按它对验证集的警告设计纪律
第 3 层（2026-09-11~12 实验 AI）：真实 GPU 实验 + 预算 + 锁定制
        产出：A 败、B 差 0.28、路由败（HE 不迁移）、等权平均 +0.15 过线
        并反过来确认了第 2 层"细节模块不是银弹""76 张验证集不可信选模"的预言
```

三层共同得出的收敛判断（这是整个 experiment 目录真正的"结论"）：

1. **MA 的瓶颈没有被证明是分辨率**：E4/E4v2/A 三次带细节通路的尝试，全部没换来 MA IoU 的真实提升（24.11→24.13→20 左右）；EX 面积与 MA 相近但 IoU 高一倍，说明对比度/形态混淆至少与尺寸同权。
2. **这套实验系统最大的敌人是统计功效**：76 张 val（SE 阳性 24 张）、单种子、test 参与路线选择——任何小于 1pp 的差别在其中既产生不了也验证不了。0.15pp 的最终提升，按这个体系的噪声水平根本无法分辨真伪，所以报告自己拒绝宣称显著。
3. **可复现性靠的是锁定文件而非记忆**：mean_ensemble_lock / mean_test_lock / ensemble_selection_lock / test_selection_lock 在**看 test 之前**就把方案、门限、协议钉死并留下 UTC 时间戳，这比任何事后声明都硬。
4. **负结果被完整保留**：阶段 2 的 41.82、A 的失败、Tversky 崩溃、三次关机/评估事故，全部有日志可查——"保留失败结果"写进了承诺并且做到了。

## 第 8 章 术语速查（看懂原文的最低配置）

- **mIoU**：四类各自累计交并比后的平均，本项目唯一主指标；背景不计入。
- **AUPR / mAUPR**：在 11 个阈值（0~1 步长 0.1）上累计出 PR 点，sklearn `auc(recall, precision)` 类内面积，再对 4 类平均。阈值网格端点问题见 4.7。
- **TTA**：测试时增强（翻转/多尺度再平均）。本轮全部未用，有就写没有。
- **BN 运行统计**：BatchNorm 推理用的均值/方差。多尺度输入 + batch=2 时它被混合分布污染；冻结（本轮 B）或换 GN（诊断建议）都是对症动作。
- **零初始化残差**：修正头最后一层权重置 0，初始输出严格恒等于基准模型，训练从"无害"开始。
- **锁定文件**：实验开始前把方案、门限、协议写成 JSON 落盘存档，事后不许改，防止"看了 test 再挑方案"。
- **证据等级 A/B/C/D**：A=代码/日志直接确证；B=多记录一致未复算；C=合理但可检验的假说；D=未核实。引用诊断报告结论时先看它的等级标注。
- **tier A/B/C（划分文件里）**：每张图按 SE 阳性/阴性/纯背景的分层标签，保证 SE 在三个集合中成比例。
