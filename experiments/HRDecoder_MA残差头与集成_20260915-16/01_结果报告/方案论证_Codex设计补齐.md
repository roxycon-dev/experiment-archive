## 一、先纠正一个关键误会：Codex 押注的方案从未被真正执行过

Codex 在 R1 诊断报告里把「语义条件下的 MA 细节残差修正」定为**唯一建议押注的方法方向**，并给了非常具体的设计。R2 的 A 方案号称实现了它，但对照代码看，**两处关键设计没落地**。

### 设计要求 vs 实际实现

| Codex 的设计要求（R1 报告 §4 优先级二） | A 方案实际做的事 | 差距 |
|---|---|---|
| `MA最终logit = MA基准logit + 修正头(原图细节特征, 对齐的粗语义特征, **基准MA分数**)` | `residual = fusion(cat([detail, semantic]))` —— **只有两个输入，基准 MA 分数没进去** | ❌ 少一个输入 |
| 「**冻结成熟基准网络及其 BN 统计，只训练这个修正头**」；「其余三类不下降是由**实现隔离**保证的」 | 全网络低学习率微调，只冻结了 BN 统计 | ❌ 冻结范围完全不同 |
| 「若要让主干联合微调，那是**另一个需要对照的干预**」 | A 做的就是联合微调 | ❌ 测的是另一件事 |

**证据**：
- `repo/hr100_refinement.py:23-29` —— `SemanticMAResidual.forward(self, image, semantics)`，两个入参，`fusion` 只 `cat([detail, semantic])`
- `D:\dataset\experiment\autodl100\实施记录.md:3` —— 「A/B 均保留 E4 已有分支，A 额外加入语义引导 MA 残差，B 不加入；二者同样使用 0.02 权重 MA 正像素/难负样本辅助损失、固定 BN 运行统计、低学习率微调」
- `repo/hr100_a.py` / `hr100_b.py` —— 两者唯一差异就是 `semantic_refinement` True/False

### 一个反常现象，正好印证了上面的判断

A 方案 8000 步结果：**val 最高 38.632@1000，最终 38.265 —— 比它的起点 E4 的 38.766 还低。**

如果只是加了一个**零初始化**的 MA 残差头（初始时残差恒为 0，模型行为等于原模型），按理不可能把整网拖低 0.5 点。唯一的解释是：**整网在动**。这恰恰说明「只训头」这个前提没有成立。

**结论：A 方案的失败，不能用来否定 Codex 的设计。那个设计到现在还是未验证状态。**

## 二、为什么这个方向值得重做——四条证据

**① MA 是 4 倍杠杆，而且它是最低分**
```
mIoU = (EX + HE + SE + MA) / 4
当前最好：53.74 + 44.27 + 50.20 + 24.38 → 43.15
```
MA 只有 **24.38**，全场最低。MA 每涨 1 点，mIoU 涨 **0.25**；EX 涨 1 点也只涨 0.25，但 EX 已经在 53.7 高位，空间小得多。

**② MA 的瓶颈不是「工作点」，是判别能力**

| 模型 | MA IoU | MA 精确率 | MA 召回 |
|---|---:|---:|---:|
| baseline | 24.11 | 46.17 | 33.54 |
| E4（注入原图细节） | **24.13** | 38.44 | **39.32** |

E4 把召回从 33.5 推到 39.3（+5.8），精确率从 46.2 掉到 38.4（−7.8），**IoU 纹丝不动（24.11 → 24.13）**。

这是典型的「只是在 P-R 曲线上滑了一个位置，没有把曲线整体抬起来」。Codex 对原因的判断是：**细节头拿不到语义条件，分不清那个暗点到底是 MA、小 HE、血管还是背景**。所以它只能靠「多预测一点」来换召回，代价是误检。

**③ 零初始化 + 冻结主干 = 结构上保证不把其他三类做坏**

这是设计里最聪明的一点。A 方案没做到，所以整网漂移；补齐后，EX/HE/SE 的输出**逐位不变**，只动 MA 通道。收益归因天然干净。

**④ 今晚的新证据正好支持「多视角互补」的价值**

我昨晚的集成实验：D+B+E4+TTA 把 **HE 从 41.67 拉到 44.27（+2.60）**，而 HE 恰是 D 方案退步最严重的类。这说明**换角度看同一个问题能纠正单模型的类别性错误**——MA 缺的正是这种能力，而语义条件化就是给它换一个「能区分相似结构」的视角。

## 三、要改的三处（都很小，且互不耦合）

**改动 1：给残差头补上第三个输入**（`repo/hr100_refinement.py:23-29`）
```python
# 现在
def forward(self, image, semantics):
    detail   = self.detail(image)
    semantic = F.interpolate(self.semantic(semantics), size=detail.shape[-2:], ...)
    residual = self.fusion(torch.cat([detail, semantic], 1))
```
```python
# 改成（补 base MA logit）
def forward(self, image, semantics, base_ma):
    detail   = self.detail(image)
    semantic = F.interpolate(self.semantic(semantics), size=detail.shape[-2:], ...)
    base     = F.interpolate(base_ma, size=detail.shape[-2:], ...)
    residual = self.fusion(torch.cat([detail, semantic, base], 1))
```
`fusion` 首层输入通道 64 → 96。

**改动 2：调用处同步传参**（`repo/hr100_refinement.py:62-66`）
```python
ma = logits[:, 3:4] + self.ma_refiner(img, semantics, logits[:, 3:4])
```

**改动 3：新增「只训头」开关**（在 `HRPlusRefinement` 上，或直接写个新 segmentor）
- `backbone` / `decode_head` / `detail_branch` / `detail_head` / `detail_scale` 全部 `requires_grad_(False)`
- BN 全部 `eval()`
- 只有 `ma_refiner` 可训练
- **加一个断言**：训练前后 base 参数哈希不变（这是「隔离」是否真的成立的硬检验）

### 缺口怎么补：两种分摊方式，难度差很多

目标 45.35，当前 43.15，缺 **+2.20**（总计 +8.81 分配到四类）。

| 分摊方式 | 需要达到 | 现实性 |
|---|---|---|
| **全部由 MA 扛** | MA 24.38 → **33.19**（+8.81） | 相当于在召回 50% 处精确率要从约 35% 提到 50%。跳跃很大，但 MA 是唯一有这么大绝对空间的类 |
| **四类分摊**（更现实） | EX +1.5 / HE +2.5 / SE +2.0 / MA +2.8 → 55.2 / 46.8 / 52.2 / 27.2 | 每类只动 1.5~2.8 点，比单靠 MA 温和得多；但需要的是**通用能力提升**，不是单点修补 |

**这意味着 P1 若只做 MA，最好也只能把缺口补掉一部分。** 它的真实价值在于：
1. 它是对 Codex 那个具体假说的**干净证伪或证实**——这本身就是论文里可写的内容
2. 如果它证明「语义条件能提升 MA 的 P-R 曲线」，那条机制就能复制到 HE（第二大空间，44.27 vs EX 的 53.74）
3. 结构上它不会让已有成绩变差（冻结主干 + 零初始化 → 最差等于现状）

## 五、判据：这次必须事前定死，避免又一次「没法归因」

1. **不要只报 MA IoU 涨了。** 真正的判据是 **P-R 曲线整体上移** —— 具体说，**在相同召回下精确率提高**。如果又是召回涨、精确率跌，那就是又一次工作点移动，判为失败。
2. **EX / HE / SE 必须逐位不变**（主干冻结的结构保证）。如果变了，说明冻结没做干净，结果作废。
3. **同协议对照**：主指标仍用 test mIoU@0.5、227 张、与 D / D+B+E4 完全一致的评测路径。
4. **基线要包含「零初始化恒等」检验**：未训练时，新模型的输出必须与 D 逐位相同。这验证「不训练 = 不改变」。
5. 验证集仍不可靠（76 张、val→test 排序已两次反转），**可以用 val 筛方案，但别用 val 数字预测 test**。

## 六、诚实的风险与边界

- **MA 的标注本身可能有上限。** R1 报告提过这一点，且 E4 的实验也间接支持——信息可能真的不够。
- **冻结主干是双刃剑。** 如果细节+语义仍分不出误检，说明信息量不足，那就该停止堆模块，而不是加更多头。
- **尺度问题仍然存在但已澄清。** R1 §2.2 纠正了一个单位错误：原始 tif 未被统一缩放到 2048²，所以「MA 中位面积 48px²」没有代码支撑。但 R1 同时指出 **EX 中位面积 56 与 MA 的 48 接近，IoU 却差了近 6 倍** —— 说明主导因素是对比度/形态/分类混淆，**不是单纯分辨率**。这正好支持「语义条件化」这条路，而不是继续堆分辨率。
- **统计效力仍然弱**：单种子、无置信区间，任何 <1 点的变化都不能声称显著。
