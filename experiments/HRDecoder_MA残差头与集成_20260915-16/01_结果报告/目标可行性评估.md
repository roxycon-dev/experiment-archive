## 一、先说结论：你的目标需要对齐现实

你给的目标是 **test mIoU 45.35**（= 历史 baseline 42.20 + 3.15），理想目标是**提升 10% 以上**。

**我必须直说：45.35 从当前这条路线上，今晚达不到。** 这不是执行意愿的问题，是有数据支撑的判断。理由如下。

### 全部历史结果（同划分 454/76/227，阈值 0.5，无 TTA）

| 模型 | val mIoU | test mIoU | 备注 |
|---|---:|---:|---|
| 历史 baseline | 39.39 | **42.20** | 从未重跑，仅作对照 |
| E4@36k | 38.77 | 41.63 | |
| B@3k | 39.21 | 41.92 | |
| 集成 E4+B | 39.54 | **42.35** | +0.15 |
| **D@2k** | **41.62** | **42.58** | +0.38 ← 当前最好 |
| L（今晚） | ? | ? | 进行中 |

### 为什么 45.35 够不到

**最关键的证据是 D 方案本身揭示的矛盾：**

| | 相对 baseline |
|---|---:|
| D 的**验证**提升 | **+2.23 个百分点** |
| D 的**测试**提升 | **+0.38 个百分点** |

**验证涨了 2.23，测试只涨 0.38——收益在迁移过程中损失了 83%。**

这不是偶然。日志里出现过两次同样的现象：
- 按 val 逐类路由：val 39.90 → test 41.82（排序反转）
- D 方案：val +2.23 → test +0.38

根因很明确：**验证集只有 76 张图，且各类像素比例在 train/val/test 之间差异巨大**（诊断报告给出 EX 像素占比 train/val/test = 0.2466% / 0.0728% / 0.1337%）。在这 76 张图上做的任何选择，都无法可靠外推到 227 张测试图。

**推论：即使 L 方案的 val 冲到 43～44，test 大概率也只落在 42.6～43.0 区间。** 用 val 门槛去推算 test 目标，在数学上就是不可靠的（Codex 自己在日志里承认过："验证 42.4 与测试 45.35 没有确定的换算关系"）。

### 量级差距

要达到 45.35，需要从 42.58 再涨 **+2.77 个百分点**。而过去全部实验里，**单次最大 test 提升是 +0.38**。要求的是历史最大增量的 **7.3 倍**。

"理想 +10%" 更远：若指相对提升 10%，目标约 46.4；若指绝对 +10 点，即 52.2——后者在任何已发表的 DDR 分割工作里都不存在。

### 子代理的 2 个"阻断项"为什么是误报

它们报：
1. 🔴 `load_state_dict(strict=True)` 会因 checkpoint 含 `ma_refiner.*` 而崩溃
2. 🔴 DDP `find_unused_parameters=False` 会崩

**实证反驳：**
- 直接读取 B checkpoint：顶层键是 `['backbone','decode_head','detail_branch','detail_head','detail_scale']`，**`ma_refiner` 相关键数量 = 0**
- `tools/train.py` 默认 `--launcher none` → `distributed=False` → 走 **MMDataParallel，根本不走 DDP**
- **最强证据**：D 方案用**字节完全相同**的代码已经跑完 20000 步并出了结果。只有 Lovasz 那一段是新增路径，而它已通过数值自检

这说明"多个子代理交叉检验"是有价值的（发现了 3 个真实的遗留疑点，见下），但也必须**用实证去证伪**，不能直接采信。

### 子代理发现的真实但有价值的疑点（均非阻断）

| 疑点 | 核实结论 |
|---|---|
| `self.align_corners` 可能为 None | ✅ 实测为 `False`，与 decode_head 一致 |
| `seg_fields` 可能未同步裁剪辅助标签 | ✅ 训练管线只有 `gt_semantic_seg` 一个标签字段，且它**永远**被显式裁剪 |
| 评估侧 `ignore_index` 未透传，255 会被当 FP | ✅ 抽样 7466 万像素，**原始数据 0 个 255**（只来自训练时旋转填充），对 val/test 不成立 |
| Dice `smooth=1e-5` 导致空标签图梯度极弱 | ⚠️ **真实存在，但 D 方案也是 1e-5**，D→L 未变，不影响单变量对照；是**独立的可改进点** |
| 预检脚本只跑 1 张 val 图，抓不到评估类 bug | ⚠️ 真实盲区，故我额外独立核验了评估链路 |

## 三、真正有可能提升 test 的杠杆（按性价比排序）

既然"再调损失"和"再加模块"都被数据证明收益很小，我把注意力转向**尚未尝试、且不需要重新训练**的手段：

### 🥇 杠杆 1：TTA（测试时增强）—— 从未尝试过

- 现状：全部实验 `TTA = false`
- 做法：水平翻转 + 多尺度推理，概率平均
- 成本：**只需推理时间**（约 3 倍），227 张测试图 ≈ 15-25 分钟 ≈ **0.5-0.8 元**
- 预期：分割任务上通常 **+0.3 ~ +1.5pp**
- 优势：**不改变模型、不需要训练、可对所有已有 checkpoint 复用**
- 风险：需要保证与 baseline 的公平对照（baseline 也应同样加 TTA）

### 🥈 杠杆 2：扩大集成——从 2 模型到 4 模型

- 现状：只集成过 E4 + B 两模型（42.35）
- 可加入：D@2000（42.58 已含 B 融合）、L@best
- 成本：纯推理，约 20 分钟
- 预期：+0.1 ~ +0.4pp
- 注意：必须报告"这是集成，不是单模型创新"

### 🥉 杠杆 3：多随机种子 —— 降低选择噪声

- 现状：全部单种子（seed 42），无置信区间
- 做法：换 1-2 个种子重训，观察方差
- 成本：每个种子约 2.2 小时 / 4.5 元
- 价值：主要作用是**判断 +0.38 是否在噪声内**，而不是提升指标

### ❌ 不建议的
- 继续延长 D 的训练（已验证 2000 步后无提升）
- 靠调 test 阈值把数字凑上去（这是 test-peeking，论文会被拒）
- 在这条路线上追加模块（两轮实验已证伪）

### 现实上限估计

把杠杆 1 + 2 都做上，**乐观估计 test 落在 43.0 ~ 43.6**。距 45.35 仍有约 2 个百分点的硬缺口。

**要真正跨越这 2 个百分点，需要的不是调参，而是换赛道：**
- 引入外部数据/预训练（如 IDF 眼底预训练、更大规模 DDR 训练）
- 换更强的分割骨干（如 SAM/医学专用基础模型的适配）
- 从"4类平均 IoU"这个指标定义出发重新设计（MA 只有 24.7，严重拖累平均；若有正当理由重新定义评估口径，收益会远大于任何模块）

以上都超出今晚的算力与验证周期。
