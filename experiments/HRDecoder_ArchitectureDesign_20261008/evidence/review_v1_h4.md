# H4 反例式复核（v1）

审查范围：`01_架构设计与研究论证.md` 第175–205、255–291、311–319行，`02_架构规格.json` 的 `H4`、`student_fusion`、`training` 字段；对照原配置与旧 H4 源码。只做源码/公式核查和小型 CPU 数值计算，没有训练，也没有真实模型推理。以下“事实”指文件直接规定的内容；“推断”指由这些规定推出的后果。

## 结论

当前草案已披露 H4 输入会随主网漂移、1,600步并非新模型的最优证据，也正确处理了稳定融合 logit 的零初始化恒等式。以下六项仍需在实现/报告中明确：训练与推理空间分布、1,600步历史选点与曝光差、BN冻结后的动态输入、`±6`限幅可达性、f7特征可逆性边界、valid mask和空前景Dice约简。f7 在未饱和区没有丢掉数学自由度，但没有显式暴露两个锚点差值，截断后也不再可逆。

## 1. 训练/推理空间契约仍不一致

**事实。** 规格写 H4 训练网格为“augmented 2048 canvas”，推理网格为“branch logit restore 后的 original image shape”（`02_架构规格.json` 第101–102行）。主方案又规定推理时先把三路 logit 恢复到原图尺寸，再 sigmoid、融合并送 H4（设计稿第315–319行）。实际训练基线先按 `ratio_range=(0.5,2.0)` resize，再随机裁 2048、翻转、旋转±45°，且旋转/Pad 的分割填充值为0；测试则固定拉伸至2048、无随机 crop/flip（`autodl100/work/HRDecoder/configs/_base_/datasets/hr_ddr_2048.py` 第25–53行）。

**推断/反例。** 两个张量都可能是2048边长，但 H4 的输入对应不同尺度与上下文：训练中局部卷积看到变尺度裁片和旋转边缘，推理中看到整幅、确定性 resize 后再恢复到 `ori_shape` 的预测/RGB。两个连续3×3卷积的有效空间感受野是5×5；训练每个邻域代表的原图范围随0.5–2.0缩放变化，且随机裁边界可落在视野内，推理网格则由原图尺寸决定。若原图尺寸不等于2048，张量网格本身还不同；本次没有核验数据文件的原始尺寸，不能把该条件说成已发生。即便全是2048²，随机 crop/rotate 与整图确定性推理的分布差异仍然成立。

**可选修复及代价。** 其一，让 H4 在训练和推理都工作在固定2048测试画布上，最后再恢复输出尺寸；这会改变当前“恢复 logits 后再 sigmoid/融合”的次序，需做整图/边缘和零初始化 parity 检验。其二，保留原图网格部署，训练时把 RGB、三路概率、标签及有效 mask 对齐到原图坐标并覆盖部署尺度；需额外插值/几何一致性处理，且可能要全图 H4 训练视图或额外前向。仅声明“同批、同几何”并不能解决部署网格不同。

## 2. 末段1,600步的“公平”边界

**事实。** 新 H4 只在主网第38,401–40,000步更新，方案明确不是额外取批或额外 backbone 更新，但计有1,600次独立 Adam 更新（设计稿第257–291行；规格 `H4.active_global_updates_inclusive`、`optimizer_updates`）。设计稿第287行将1,600称为旧 H4 的“有效观察点”，同时也承认不能据此证明新 H4 最优。旧 H4 实际训练2,000步、每400步看一次 val，`best` 在1,600步；旧头训练在冻结模型输出上，使用1024 crop，脚本逐步随机取一个训练样本。新计划则在动态更新的主网输出上，用全局 batch=2 的同一批训练 H4（旧 H4 代码见 `HRDecoder_审查轮_20260916/tools/h4_post_fusion_corrector.py` 第105–120、171–210、213–222行；旧 pipeline 见 `hrdecoder_plus3/repo/configs/lesion/exp/hrplus_patch_dice.py` 第12–23行）。

**推断/反例。** 旧的“val 最佳1600”本身是多次验证后的选择；将它用于新结构是一个由同一 val 结果导出的时长先验，而不是独立的预算依据。更具体地，旧1600步约为1600次单图曝光，新1600个全局步对应3200张图的 H4 曝光；输入分辨率、模型冻结状态、预测分布也都不同，因此“1600步可移植”不成立。总主网批次仍是40,000，故可称主优化步数公平；不能称总优化器调用数、额外高分辨率计算量或 H4 样本曝光量与无 H4 基线相同。方案已把这些计数分开，这是优点，但在比较段应继续按此口径报告。

**可选修复及代价。** 将1,600固定为预注册的工程预算，并明确来源是历史 val 选择；所有带 H4 的对照用相同活动区间/曝光，报告1,600次头更新与额外 MAC，不在新 val 上扫描末段节点。若要求按旧 H4 的单图曝光量对齐，新 H4 只应有约800个 batch=2 更新，但这会缩短其优化时长并改变原拟议日程。现方案的代价最低是保持1,600，承认它是预算选择而非最优性结论。

## 3. 冻结 BN running stats 不等于固定 H4 输入

**事实。** 第38,401步起只冻结原模型 BN running mean/variance，BN affine 和“所有主网权重”继续训练（设计稿第283行；规格第144–146行）；H4 输入和基准 logit detach，L/C 仍由主损失与 KD 更新（设计稿第201、277–287行）。原训练 schedule 是线性 poly，峰值学习率0.005、40,000步结束、`power=1`（`poly10warm.py` 第8–15行；规格第136–146行）。

**推断/反例。** 按该 schedule，38,401步的主 LR 仍约为 `0.005×(1−38401/40000)=1.99875e−4`，约峰值的4%；BN affine、共享解码头与 L/C 权重都继续更新。冻结 running stats 只避免批统计和部署统计切换，不固定前向函数。因而 H4 的 q/pL/pC 仍可能逐步漂移，`detach` 只隔离梯度，不能让输入 stationary。草案在第287行已承认这一点；需要避免在报告中把 late-BN 描述成解决了动态输入问题。

**可选修复及代价。** 保留当前低成本方案，但把 H4 在38,400、39,200、40,000步读到的 q/pL/pC 分布分位数、L/C差异和 delta 饱和率作为必报诊断；明确每步 H4 使用主 SGD 更新前还是更新后的预测。若要把 H4 输入真正固定，需冻结相关主网/分支参数（或先训完主网再拟合 H4），会改变“同批并行、主网40k持续训练”的方案；只冻结 BN buffers 达不到该效果。对照模型应统一 late-BN 规则，设计稿已经提出这一点。

## 4. `6*tanh` 让部分 MA 错误不可翻转

**事实。** H4 输出 `p_out=σ(logit(q)+6 tanh(h))`，输出基准 logit 不做概率 clamp（设计稿第187–199行；规格第94–99行）。稳定 logit 融合保留零末层时的精确恒等式；这是修复旧 H4 在极端概率上 clamp 后不再恒等的正确做法。

**推导与 CPU 反例。** 对固定 q，H4 可达区间为 `σ(logit(q)−6) < p_out < σ(logit(q)+6)`。要把 q 翻成严格大于0.5，必须 `q > σ(−6)=0.002472623…`；要把 q 从正类压到 `≤0.5`，必须 `q < σ(6)=0.997527377…`。例如 q=0.0001 时，即使残差趋近+6，最高只到0.038782；q=0.999时，即使残差趋近−6，最低仍为0.712336。边界由于 `tanh` 严格小于1也不可达。若 GT 与这些高置信度 q 相反，当前 H4 的 GT loss 仍会要求翻转，但结构无法实现；当 tanh 进入饱和区，反向梯度还会变小。以上是公式的 CPU 数值计算，不涉及模型预测。

**可选修复及代价。** 先报告 GT 有效像素中落入上述不可翻转区的正/负 MA 比例和 delta 饱和率，再决定是否扩大上限。把上限从6提高到12会把阈值扩至约`σ(−12)=6.1e−6`/`σ(12)=0.999994`，仍非任意 q 的保证且增加 tanh 饱和风险。去掉硬 tanh、直接输出 logit residual 可避免有限上限造成的不可达，但需另行约束数值/校准并验证训练稳定性；在没有真实预测统计前无法定量选择。

## 5. f7 的锚点/差值信息：未饱和时可逆，差值没有显式展开

**事实。** f7 为 RGB、`logitε(q)`、`logitε(pL)`、`logitε(pC)`、`pL−pC`（设计稿第177–199行；规格第89–99行）。融合权重为 α=0.5625、β=0.1875、γ=0.25，q=αpA+βpL+γpC（设计稿第163–171行）。

**推导。** 在三个概率均处于 clamp 内时，三个 logit 特征可逆回 q/pL/pC；由于 α≠0，锚点可由 `pA=(q−βpL−γpC)/α` 精确还原。因此不能说 f7 在数学上丢失了 pA 或两维差异自由度。相反，在该未饱和区，额外的 `pL−pC` 已由 pL、pC 确定，是冗余提示。可是它没有直接输入 KD 所定义的两个锚点差 `pL−pA` 和 `pC−pA`；H4 必须从三个 logit 特征先学回概率关系，再形成这两个量。logit clamp 一旦触发，概率幅度被截平，逆解 pA 不再可靠；单独的 pL−pC 只补回一个相对差，不补回共同基线。这是表示偏置/边界信息丢失，不是一般区域的秩亏。

**可选修复及代价。** 若“让 H4 使用两种内部差异”是明确论据，可把同样7通道排为 `[RGB(3), logit(q), logit(pA), pL−pA, pC−pA]`，直接暴露锚点及两差，代价是更改 H4 输入合同、重新训练并重新检验输入尺度；旧 H4 本就不可复用。若 H4 仅被视作学 q 的 GT 后校准器，保留当前输入也可，但不应声称它直接读取了两个 KD 差值。

## 6. Ignore/padding 与空前景 Dice

**事实。** 新损失意图将 ignore/padding 从 BCE、Dice 交集及分母全部排除（设计稿第255–267行；规格第106行）。然而基线随机旋转和 Pad 把分割填充值设为0（`hr_ddr_2048.py` 第31–35行），0也是合法背景标签。旧 H4 则直接将255改为0后全像素计算 BCE 和 Dice（旧源码第198–202行），新方案明确不应沿用。

**实现缺口。** 从变换后的 `gt!=255` 不能恢复哪些背景0来自真实图像、哪些来自旋转/几何 padding。若没有从原图全1 mask 出发、按相同旋转/裁剪/Pad 几何独立传播的 valid mask，所谓排除 padding 实际做不到；教师 support mask 也会误纳源图外背景。需在数据流水线定义该 mask 的插值规则和 batch 对齐，不能只依赖标签值。

**空 MA 推导。** 若按单图/单类计算且所有有效像素的 y=0，则 `Σvpy=0`，Dice 项恒为1，关于 p 的梯度严格为0；该样本的 false positive 只受0.5 BCE 一半的损失抑制。若把 batch 中所有图像像素先合并，只要 batch 里至少一张有 MA，空 MA 图的预测会进入公共 `Σvp²` 分母并获得 Dice 梯度；若整批都无 MA，梯度仍为0。因此规格还需写明 Dice 是按图计算再平均，还是跨 batch 聚合。另若某样本/批次 `Σv=0`，空集合上的 `BCE_valid` 均值可能为 NaN；应显式跳过该项/样本，Dice 也不应作为有效样本计入均值。

**可选修复及代价。** 最小修复是保存独立几何 valid mask，定义空集合 skip 及 Dice 约简轴，并记录 valid 像素数和空 MA 样本比例；此时接受空前景 Dice 无梯度、由 BCE 提供背景信号。若希望 Dice 本身也处罚空前景误报，可用带分子平滑的 Dice 或改用专门负类项，但这改变“沿用平方分母 Dice、numerator no smoothing”的锁定目标，需做匹配消融，不能称为纯粹的 ignore bug 修复。
