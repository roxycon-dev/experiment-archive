# v2 H4 与主路径接口复审

审查范围：`04_v2_修订架构.md` 的工作网格、H4 输入/梯度、tile、原 HRDecoder 接口及 L/C 特征接口。只读设计与源码；未训练、未运行学生或教师推理。把“确定不一致/接口缺口”与“方案成立但仍待测”分开。

## 结论

v2 在 H4 工作网格和 stop-gradient 语义上比 v1 自洽：主路径输出、H4 输入及 H4 MA 输出都留在2048输入画布，最终只在模型外恢复原图 logits；H4 loss 只更新头，未经过 H4 的 z0/z1/z2 仍由主损失训练。两层3×3卷积的有效半径是2像素，所以512核心块配2像素 halo 足够；但边界取片规则必须写明，当前工作区也没有能复现文中所称 v2 随机张量/tile 探针的实现。

有两项确定的执行契约问题：根目录 `02_架构规格.json` 和 `verify_design.py` 仍是 v1；此外，原 HRDecoder 当前接口不返回 L/C 所需的原生多尺度特征，无法同时满足“原 HRDecoder不改”和“不额外前向 HRNet”，除非明确允许只重构 forward 接口并在一次 backbone 前向中同时返回 z0 与 F1–F4。

## 1. 已确认的不一致：v2正文、规格 JSON 与检查脚本不同步

v2正文称自己替代v1（第3、5、16–17行），但根目录 `02_架构规格.json` 仍规定旧的学生概率融合、H4 输入 `logit(q), logit(pL), logit(pC), pL−pC`、推理在恢复原图后运行 H4、仅末段1,600次 H4 更新（JSON第81–112行）。这与 v2 的逐级 logit 残差、`clip(z0,z1,z2), p2−p0`、2048网格 H4、全程40,000次 H4 更新直接冲突（正文第103–127、163–173行）。

检查脚本也仍读取旧规格：`verify_design.py` 第10行读根目录 `02_架构规格.json`，第23–29行断言旧的 C=58,372 参数计数；文件首行声明“no torch, model loading, inference or training”。配套 `evidence/design_verification.json` 记录 H4=1,600 updates、总参数87,737。这些内容不能佐证正文第208行所说的 v2 小尺寸随机张量、detach梯度隔离与tile halo探针。可能存在未入库的手工探针，但当前交付中不可复核。

**必要修正：** 若根目录02和验证文件要作为当前实现契约，就更新成v2并提交对应探针与输出；若要保留v1，只把旧规格/验证文件移入 `archive/v1`，在正文中标出v2唯一的规格与验证入口。否则实现者可能按旧 H4 输入和时钟搭建。

## 2. 原 HRDecoder 的公开输出不足以连接新分支

**源码事实。** 原 `HRDecoder.encode_decode` 先执行 `self.extract_feat(lr_img)`，再用 `_transform_inputs` 将四尺度都 resize 到 F1 网格并拼成720通道 `lr_feat`，最后拼接/融合 LR 与 HR logits；函数只返回最终 `fuse_logit`（`autodl100/work/HRDecoder/mmseg/models/segmentors/HRDecoder.py` 第145–151、216–233行）。训练的 `forward_train` 同样把 backbone 结果压成 `lr_feat` 后只构造 base logits 和 loss，不返回原生 F1/F2/F3/F4（第244–276行）。

v2 的 L 和 C 却分别要求 F1/F2 与原生 F1–F4 网格（正文第91、97行），并要求同一批计算出的 z0（第83、106行）；正文还要求唯一 HRNet、不额外前向（第5、26–27行；第166行）。如果外部 wrapper 先调 `encode_decode()` 得 z0，再调 `extract_feat()` 取 F1–F4，就会跑两遍 HRNet；如果只使用现有 `lr_feat`，F2–F4 已被上采样到 F1 的256²网格，不能再当作 C 所写的原生128²/64²/32²路径。

**确定结论与修正边界。** 这不是参数结构本身不可实现，而是“原 HRDecoder不改”的接口说法不完整。保留原 backbone/head 参数及 z0 数值路径是可行的；实现需在一次 `extract_feat` 后保留特征元组，另行构造现有 `lr_feat` 供原解码头使用，并从同次前向返回 `{z0, F1, F2, F3, F4}` 给 L/C/H4。应把“原 HRDecoder不改”改成“原参数化路径/权重不改，允许 forward 接口扩展”；否则“原类不改”与单次 HRNet 前向不能同时保证。

## 3. 网格、H4输入和 detach：数学/接口顺序基本一致

v2规定 H4 输入为 `[已归一化RGB(3), clip(z0_MA), clip(z1_MA), clip(z2_MA), p2_MA−p0_MA]`，共7通道，与7→16→16→1的头相符（正文第117–123行）。`clip` 到 ±log(9999) 等价于实数域 `logit(clamp(sigmoid(z),1e−4,1−1e−4))`；差值则是概率域差，不是 logit 差。必须按这一混合域实现，不能把末通道误写成 `z2−z0`。

本地基线归一化为 mean `[81.205,50.636,21.216]`、std `[76.252,48.798,21.625]`、`to_rgb=True`（`configs/_base_/datasets/hr_ddr_2048.py` 第10–11行）。正文只写“归一化RGB”，未重述数值；实施契约最好明确 H4 复用已经 Normalize 的 `img`，不得二次反归一化/归一化。

网格顺序在内部是连贯的：原 `HRDecoder.encode_decode` 输出与输入画布同尺寸（第216–233行），自定义 `LesionEncoderDecoder.whole_inference` 在 `encode_decode` 返回后才裁 padding/恢复 `ori_shape`，随后 `inference` 才对 logits 做 sigmoid（`lesion_encoder_decoder.py` 第101–123、140–160行）。因此 H4 应嵌在 `encode_decode` 的2048 logits路径内、恢复原图之前；v2第127行“先完成四类 z_out，再统一恢复原图 logits”能在零初始化时复现基线顺序。若把 H4 当作模型外 post-process 加在 `whole_inference` 之后，就会回到原图网格，违反 v2。

detach语义也成立：`sg(z2_MA)` 是数值恒等的 H4 基准，`sg(X_H)` 切断由 H4 loss 经特征回到 z0/z1/z2 的路径；H4头自身仍可训练。正文第125行指定主 GT/KD 直接监督未经过 H4 的 z2，故 MA 主分支不会因 detach 停训。需在实现验收中分别检查“仅 H4 loss 对 z0/z1/z2 梯度为0”和“主损失对 z2/L/C 梯度非零”，不能只检查总 loss 的梯度。

训练和推理的 H4 tensor 网格现都为2048，消除了 v1 的输出网格尺寸与恢复顺序差异；训练仍有 ratio/crop/rotate，而推理是固定测试变换，这是增强带来的物理视野差异，不是同网格契约的数学矛盾。应将 v2 的“同工作尺度”理解为张量坐标一致，不宣称训练、部署每个5×5邻域覆盖相同相机视野。

## 4. tile halo2：半径正确，边界实现和验证尚未落地

H4两层3×3、stride1卷积后接1×1，无空间归一化（正文第119、131行）。`clip(z*)`、sigmoid及 `p2−p0` 都是逐像素操作；H4卷积链的总空间半径恰为2。因此内部512×512输出 core 只要读到其四周各2像素的真实 `X_H`，再丢弃 halo 输出，就能与整图前向一致。内部 tile 边界不能用0替代邻居，正文对此规定正确。

外边界需再写具体：安全办法是把 halo 输入裁到真实2048画布范围，并让两层卷积各自在真正的画布边缘执行自己的 `padding=1`；不要先给整幅 `X_H` 人工加2圈零、再对两层卷积照常使用 padding，因为第一层会在画布外算出非零隐藏特征，第二层可能把这些值卷回边缘输出。该区别不改变“halo2足够”的结论，但会决定边缘是否与整图一致。

正文没有明确 tile 只用于推理还是也用于训练。推理时分块可降低 H4 中间激活峰值。训练时，若把各块输出拼起来后对整图 Dice/BCE 统一反传，普通 autograd 会保留所有块的反向所需激活；分块前向本身未必降低总峰值。若改为各块单独回传，Dice 的全图交并/平方分母约简也必须保持等价。建议把“512 tile”标成推理实现优化，先用随机输入比较全图与分块在内部接缝、四边及四角的最大误差；如用于训练，再另证内存与全图损失等价。

## 5. 一处边界不等式应修正

正文第133行称 `q>σ(6)` 时无法翻负，但同句后又指出边界等号受 tanh 有限输出和严格阈值影响。因为 `6tanh(h)∈(−6,6)`，当 `q=σ(6)` 时最小输出只趋近0.5、不能达到；采用 `p>0.5` 判正时它同样不能翻为负。精确条件应写为：`q≤σ(−6)` 不能翻正；`q≥σ(6)` 不能翻负。该点不影响方案，但当前 `>` 与后面的边界说明不一致。

## 必要修正汇总

1. 统一根目录 v2 规格、校验脚本和证据；当前可复核 JSON 仍是 v1。
2. 明确一次 backbone 前向同时暴露 z0 与原生 F1–F4；允许扩展 forward 接口，但保留原模块与 z0 路径。
3. 将 H4 放在 `encode_decode` 内、恢复原图之前；明确 RGB 使用原规范一遍归一化后的输入张量。
4. 规定 tile 在画布边界裁 halo 的具体实现，并把随机张量整图/分块对照补成可复现证据；若训练也分块，额外验证 Dice 全图约简和峰值内存。
5. 将 `q>σ(6)` 改为 `q≥σ(6)`。

## 关闭复核（2026-10-08）

复查当前 v2 文档、根目录 JSON、`verify_design.py` 与 `evidence/design_verification_v2.json` 后，以上已确认问题在**设计/文档契约层面均已关闭**：JSON声明 v2、单次 backbone call 与 native F1–F4 接口；文档第85行说明只扩展 forward API、不改原解码算子；H4仍在2048网格、输入为归一化RGB/clip(z0,z1,z2)/sigmoid(z2)−sigmoid(z0)，stop-gradient范围和主z2监督明确；tile只用于 no-grad 推理，边界裁切/逐层padding规则明确；翻负条件已写成 `q≥σ(6)`。

规格 JSON 没有残留 `1600`、`38401` 或旧 H4 `q/pL/pC` 概率投票输入。唯一保留的 `[0.5625,0.1875,0.25]` 是教师 T2 的 A/U/S 构造权重；学生部分明确为 `logit_residual` 且 `fixed_probability_vote=false`，不是遗留学生投票。CPU 证据记录29项通过，其中 halo2 非零头全图/分块最大绝对差为 `1.49e−7`；当前脚本也确实实现了独立CPU模块、detach梯度和裁边界分块探针。本复核只读结果，没有重跑会写回 JSON 的脚本。

仍未验证的是 v2 模块与真实 HRDecoder 的完整集成（JSON `unverified` 明确列出），因此单次特征接口目前是规格已补齐、真实接线仍待未来实现验收；这是明示风险，不是当前文档内新冲突。本轮未发现新的确定性 H4 契约矛盾。
