# 架构自审记录

版本：v1→v2，2026-10-08。原版存于archive/v1。所有修订均为研究设计，不是新训练结果。

## 必须撤回的决定

1. **多数概率权重限制新信息纠错。** 固定q=.5625pA+.1875pL+.25pC，在pA≤1/9时q≤.5；主路径强阴性不能仅靠另外两路翻正。v2改为z1=z0+r1、z2=z1+r2。主网络联合学习可能改变pA，所以这是条件表达限制，不是整个v1不可学习的定理。
2. **原始差值可逆不代表有用。** 例如背景像素A=.05、U=.95、S=.05，最终T=.21875仍判对，但v1精确差匹配要求pL=.95，复制U错误。v2学习T0=A、T1=P0、T2=最终系统，取消原始成员差MSE。P0也可能局部错误，GT与KD仍须折中。
3. **粗语义出口不能单独表示细尺度修正。** v1 C只输出stride16残差。v2加F1及共享RGB stem出口到stride4；不把它称作复制DINO特征或恢复相机细节。
4. **H4网格不一致。** v1训练2048、部署原图，局部卷积与插值一般不交换。v2统一2048组合，最后恢复logits。需接受这是不同于旧H4的操作条件。
5. **从旧best@1600推断新头1600最优没有依据。** 原batch1/静态预测，新batch2/动态预测不同。v2全局40k联合更新，不新增批次，所有选点含完整结构；同样不能保证长训更好。
6. **冻结BN不是冻结模型。** 撤销末段切换，不再声称它复现旧固定专家。普通train/eval统计差异和在线输入漂移仍须实际验证。
7. **ignore不仅是255。** 原管线padding标签0；v2引入独立几何有效域，连同主损失和HR辅助的相应区域统一屏蔽。属于训练配方改动，公平对照必须共享。
8. **原KD硬阈值与小组等权不连续/高方差。** v2连续GT一致性权重，取消教师误报独立组；前景/背景固定各半质量，不对空组重新放大。加权优劣未证明。

## 审查后没有加入的修改

- 不因soft KD与GT梯度偶尔相反就判定KD错误；这也可能是正则化。没有默认采用“学生训练GT置信度更高便关闭teacher”的单边KD。
- 不扩大H4的±6边界来追求任意极端概率翻转；已有正结果支持有界校准，主残差已经能改变基准logits。
- 不加第三个encoder、DINO初始化、外部监督、动态空间门控、额外注意力或推理教师。
- 不拿CPU梯度有限、公式可逆或零步恒等，充当真实数据效果验证。

## 逐项验证与限度

机器检查结果见evidence/design_verification_v2.json，由verify_design.py生成。包括解析/实例化参数一致、形状、零步恒等、合成梯度通路、ignore/空前景、H4 tile、固定投票反例和卷积/插值不交换。具体通过项以JSON为准，不凭此证明GPU实现或最终mIoU。

三份独立v1审查：evidence/review_v1_h4.md、review_v1_objectives.md、review_v1_protocol.md。新版核心取舍由主代理负责。

## v2再次审查及关闭结果

三份复审记录为evidence/review_v2_h4.md、review_v2_objectives.md、review_v2_protocol.md。它们审阅的是文档修订过程中的快照，下列问题已在当前v2中处理：

| 复审发现 | 已做修正或验证 |
|---|---|
| logit增量相加漏掉初始logit，且端点不适用 | 明确增量和是logit(T2)−logit(T0)，加z0后才得到logit(T2)；仅对内点成立；训练不回归这些差 |
| “所有合法像素都有软信号”不符合c公式 | 改为无0.5硬阈值；极端自信错误教师可取零权重 |
| 新掩码下Dice恒等被扩大成历史训练损失恒等 | 限定为同一新v上与z0 Dice恒等，并说明只做一次sigmoid |
| H4不能翻负的边界漏等号 | 有限实数下改为q≥σ(6)；单列浮点tanh饱和边界 |
| 原HRDecoder API不能给L/C提供原生特征 | 在原`extract_feat`后保留F1–F4，同一结果供原解码与新分支；需要改返回接口，仍只提取一次骨干 |
| 规格与检查脚本仍是v1 | 根目录规格和脚本替换为v2；v1保留于archive/v1，旧检查标明被替代 |
| H4 halo外边界与训练内存含糊 | 按真实画布裁片，每层自行padding后裁中心；非零输出权重探针验证；节省激活峰值仅承诺no_grad推理，训练拼接不作此承诺 |
| C的解析MAC遗漏更细出口的额外计算 | 实例Conv hook发现不符，修正为3,734,241,280 MAC，完整新增23,632,019,456 MAC |
| KD连续性探针在零KL处可能空泛通过 | 改成float64、学生logit=1的非零KL探针，.5两侧损失差约3.80e-7 |
| 原图缓存104.90GiB是否有依据 | 454个JPG头信息与清单全部匹配；2,346,569,020像素×48字节；不宣称实测文件占用 |

当前CPU运行结果：**29项通过，0项失败**。使用PyTorch 2.6.0+cu124但显式运行CPU，随机64画布和随机多尺度特征；没有读取教师权重或训练图像，没有创建优化器或做参数优化更新。为验证零末层之后隐藏层梯度能到达，单独把输出层赋为随机非零诊断值，这不是训练结果。H4非零头tile与full最大绝对差1.49e-7；卷积与插值互换的反例差约0.307，支持统一工作网格的必要性。

单次合成通过不代表任意设备、dtype和输入都无误。完整数据管线的几何有效域与HR crop掩码尚未实现，不能把损失层面的mask不变性检查称为完整增强管线已通过。CPU探针也不验证共享HRNet的特征质量、旧H4收益迁移或40k收敛速度。

当前停止继续改结构的依据：已处理本轮确认的矛盾；可执行的小模块契约有结果；剩余不确定性需要数据和训练对照，继续凭文字更改结构或常数不会证明提升。v2是当前有证据约束的推荐设计，不是“达到完美”的声明。

尚未实测：完整HRNet接入、ImageNet文件SHA、454张teacher缓存、显存/速度、训练稳定性、40k结果、种子方差、外部泛化。它们是明确的验证边界，不用“完美”一词覆盖。
