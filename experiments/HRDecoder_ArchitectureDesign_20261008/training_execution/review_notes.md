# v3 训练执行审查

本次执行依据 `05_v3_机制重构与反驳审查.md`，旧 `02_架构规格.json` 不作为执行配置。三路教师身份、原图 FP32 缓存保持锁定；学生只加载 ImageNet W48。

## 实现与 CPU 证据

真实模型复用归档 HRDecoder 的 backbone、压缩 FCN 解码头、LR/HR 平均、四个随机 HR feature crops 与原 BN 行为。只提取一次 HRNet 特征，将 F1/F2/F3/F4 提供给 v3 私有模块。新增模块定义从经过审查的原型原样提取，新增参数 6,419,648；真实基座 65,572,420，学生合计 71,992,068。

在 128 画布、batch2 上，零末层输出与原 HRDecoder 训练前向逐位相同，全部 BN 运行缓冲和随机 HR crop 消耗的 NumPy 随机状态一致。在非零诊断末层、断开 z0 梯度的情况下，主目标可以经私有路径回到真实 HRNet；辅助梯度只累加到 L/G 和两个读出，共享主干及最终分类器保持 task-only 梯度。32 倍共同缩放后的梯度也与参考相同。这些检查不构成 CUDA AMP 验收。

20 个种子的几何重放与原管线保持 image/label 和随机抽样结果一致。软图使用同一 Resize/Crop/Flip/Rotate/Pad，离散标签 nearest；独立 v_geo 用 bilinear warp 全一源图，最终只接受支持质量 >= 1-1e-6 的像素，拒绝插值到源图外补边的区域。v_label 独立 nearest，统一掩码用于主目标、KD、分歧及 HR crop。正常眼底黑背景仍然有效。真实训练图 `007-6383-400` 的原图/标签 SHA、三路缓存 SHA、2048 变换及正负差分构造已通过。

W48 文件 SHA 是 `d2186c55782308392ae14cf179ac4840143b09abdbba81aa3f9274c795ebc960`。原构造/初始化完成后再次逐张量验证整个分割骨干等于该文件。新模块只使用隔离的 CPU RNG。服务器 torch2.0.1 的初始化状态另行锁定；本地 torch1.10 的初始化状态不冒充服务器状态，更不冒充历史 B0 运行的初始快照。

## 固定执行协议

40,000 个全局 batch、每批 2 张、一次 SGD 更新，lr=.005、momentum=.9、weight_decay=.0005。原 MMCV poly 与线性 warmup 的组合被保留：前 1500 步以当步 poly LR 再乘 warmup 系数；不会误换成仅从 0 升到固定 .005 的独立 warmup。lambda_K/lambda_D 使用 v3 的锁定分段日程。

当前主运行是完整 v3。代码提供同 mask 的原模型 `B0`、原模型加最终 KD 的 `B1`、同容量 `capacity_kd` 和普通辅助回传 `ordinary_aux`；各模式独立身份、权重目录及 smoke，不会擅自启动多组收费训练。所有研究对照尚未执行；成员坐标、Hydra 家族及其他研究诊断尚未实现，未声称已完成全部研究对照或验证创新性/精度改善。

随机增强参数的分布与原管线一致；本训练器采用固定 epoch 排列和每个曝光的独立 seed，以保证 worker/断点恢复一致。这个可恢复采样顺序不能冒称与历史 B0 每步的实际 worker RNG 轨迹相同。历史 42.20 不是本轮新复现结果。

默认单卡 BF16 autocast，损失、概率差分和统计用 FP32。BF16 不启用 FP16 GradScaler；路由函数支持两项损失以同一 scale 合并后统一 unscale。缩放与手工梯度必须一致，依据 [PyTorch 2.0 AMP 文档](https://docs.pytorch.org/docs/2.0/notes/amp_examples.html)。当前明确拒绝 WORLD_SIZE>1，避免把未经核验的手工辅助梯度当作自动完成 DDP 同步。

每 1k 保存可恢复 last.pt，包含模型、动量、完成步数、RNG、scaler 和协议身份；每 4k 在全部 76 张 val 上按原图四类、strict > .5 评估。40k 固定端点为主，best-val 为次，不用 test 选点。不会增加训练阶段，不因梯度溢出默默消耗一个应有 SGD 更新：非有限梯度会中止。

## 正式训练前的闸门

1. 454 张三路缓存全部再次读盘校验，文件 SHA 与 FP32 张量 SHA 一致，并完成 train 分歧能量/方向/协方差及类别覆盖报告。
2. 训练源码、CPU 证据、服务器真实初始化及 ImageNet 文件 SHA 匹配。
3. 切回 4090 后，用 batch2、2048、非零辅助权重跑一次独立进程 smoke，记录显存、损失和单次 SGD 更新；该 probe 更新不进入正式权重。
4. smoke 通过后，新进程重新构造 seed42 ImageNet 学生并开始 40k。代码或协议改变后必须重新 smoke。

本次无卡阶段没有正式 SGD 更新。2048 CUDA 前向/反向、显存、速度与收敛仍待第 3 项实测；CPU PASS 不替代它们。若 4090 smoke 不通过，修复后重新验收，不降低画布/批次、不加梯度累积后仍宣称原协议。
